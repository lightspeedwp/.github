# Output Conventions

Use these conventions across every design skill.

## Core rules

- Keep outputs decision-oriented and easy to scan.
- Separate evidence from interpretation.
- Mark assumptions explicitly when inputs are incomplete.
- End with concrete next actions.
- If a connector action is possible, propose it after the plain-text result rather than instead of it.

## Standard tail sections

Every deliverable should end with:

1. `Assumptions`
2. `Recommendation`
3. `Next actions`

## Capability handling

- `docs`: offer to save or update a document after producing the deliverable.
- `tracking`: offer to create tasks only when work items are concrete enough.
- `chat`: offer a short stakeholder-ready summary after the main artifact.
- `design-source`: use source artifacts when available, but do not block on them.
