# Accessibility Review Quality Check

Use this checklist when evaluating whether an accessibility review is grounded, appropriately scoped, and useful.

## Grounding checks

- Does the review distinguish what is directly visible from what still needs implementation verification?
- Does it avoid claiming compliance from static designs alone?
- Does it describe confidence appropriately when evidence is incomplete?

## Coverage checks

- Does it consider contrast, keyboard support, screen-reader implications, and mobile usability when relevant?
- Does it consider readability for older users where content density or hierarchy is a concern?
- Does it call out form, navigation, CTA, and state issues when those elements are present?

## Recommendation checks

- Are the recommendations concrete enough to act on?
- Do they explain why the issue matters to the user experience?
- Do they distinguish high-impact issues from lower-priority polish items?

## Failure signals

- Claims of WCAG compliance without sufficient evidence
- Generic accessibility advice with no connection to the artifact
- Missing high-impact issues in core tasks or flows
- Recommendations that do not explain user impact
