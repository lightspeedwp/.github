# Design Review Regression Checklist

Use this checklist when reviewing whether a critique, audit, or handoff still meets the expected quality bar.

## Core checks

- Does the output lead with the most important issues first?
- Does it separate confirmed issues from assumptions or open questions?
- Does it mention accessibility concerns when relevant?
- Does it stay scoped to the requested artifact, flow, or journey?
- Does it avoid unsupported claims about implementation or metrics?

## Brand-sensitive checks

- Does the wording stay plain-spoken and low-jargon?
- Does the tone stay clear, supportive, and practical?
- Does it avoid hype, fluff, and exaggerated claims?

## Evidence checks

- Does it cite or name the sources behind important claims when sources were used?
- Does it distinguish intended design direction from live implementation reality?

## Handoff checks

- Are behaviors, states, dependencies, edge cases, and unresolved questions explicit?
- Are acceptance criteria included when the work is implementation-oriented?
