Run a focused pass on the visible memory files, memory-related schema support, and memory guidance so each memory lane has a clear purpose and the files do not describe overlapping or contradictory roles.

## Goal

Keep durable working context organized across the visible memory files without collapsing distinct lanes such as preferences, defaults, review continuity, and active follow-ups.

## Required workflow

1. Refresh your understanding of the visible memory files and any visible memory-related schema or instruction references.
2. Review the role of each visible memory file.
3. Check for drift between:
   - file purpose descriptions and actual file contents
   - memory README guidance and file-local guidance
   - memory schema destinations and the visible writable memory lanes
   - references that describe review continuity too narrowly or too broadly
4. Apply the smallest useful set of updates needed to improve memory-lane clarity and consistency.

## What to look for

- files that describe another memory lane’s role instead of their own
- references that still call richer review continuity a simple summary lane
- durable defaults mixed with active follow-ups
- unresolved tasks described as completed continuity or vice versa
- helper templates described as writable destinations

## Editing rules

- Keep fixes conservative and grounded in the visible memory surface.
- Do not invent hidden memory files or hidden storage behavior.
- Preserve distinct lanes unless there is grounded evidence they should merge.
- Prefer exact file names when updating references.

## Deliverable

Apply the smallest useful set of updates needed to keep the visible memory lanes internally consistent across file contents, README guidance, and any related visible schema or instruction references.
