Run a focused pass on visible example files so they stay aligned with the current template, schema, and workflow vocabulary for the family they belong to.

## Goal

Catch examples that still teach an older structure, looser terminology, or stale workflow framing than the current visible package supports.

## Required workflow

1. Refresh your understanding of the current visible examples, templates, and schemas.
2. For each visible example family you inspect, compare the example against any matching visible template and schema.
3. Check for drift between:
   - example section names and template headings
   - example structure and schema-backed fields
   - example workflow naming and current package vocabulary
   - freeform example sections and newer structured template or schema expectations
4. Apply the smallest useful set of updates needed to improve example-family consistency.

## What to look for

- examples that still use older headings or wrapper sections
- examples that omit important sections present in the visible template family
- structured families where examples remain freeform
- examples that imply a broader or narrower workflow than the current package supports
- visible examples with no matching visible template or schema family

## Editing rules

- Keep fixes conservative and grounded in the visible package.
- Do not invent missing templates or schemas just because an example exists.
- If an example is a visible standalone exception, prefer clarifying that in a README rather than inventing a hidden family.
- Preserve useful example precedent unless it is clearly stale or contradictory.

## Deliverable

Apply the smallest useful set of updates needed to keep visible example families aligned with the current visible templates, schemas, and workflow vocabulary.
