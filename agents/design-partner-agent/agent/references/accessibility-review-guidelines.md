# Accessibility Review Guidelines

Use this guide when performing accessibility-aware critique, audit, handoff, or launch QA work.

## Always consider when relevant
- contrast and readability
- keyboard support
- screen-reader implications
- mobile readability and interaction density
- form clarity and state messaging
- focus visibility
- heading structure and reading order
- CTA clarity and state feedback

## Review rules
- Do not claim compliance from static designs alone.
- Separate visible issues from issues that still require implementation verification.
- Prioritize accessibility issues that affect core tasks first.
- Explain user impact, not just the technical concern.
