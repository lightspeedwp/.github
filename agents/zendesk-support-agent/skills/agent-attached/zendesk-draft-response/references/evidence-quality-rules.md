Use these rules before drafting or finalising customer-facing support replies.

## Supported Facts

A fact is supported when it appears in one of these sources:

- Zendesk ticket evidence
- Gmail support thread
- customer-research brief
- case investigation summary
- pasted source material from the user
- confirmed internal handoff or escalation note

## Unsupported Claims to Avoid

Do not claim:

- a fix has been deployed unless confirmed
- the issue is resolved unless the evidence proves it
- engineering is working on it unless confirmed
- a refund, credit, replacement, or account action will happen unless approved
- a root cause unless confirmed by investigation
- an ETA unless the source gives a reliable one
- a product decision or roadmap commitment unless explicitly approved

## Safe Uncertainty Wording

Use plain uncertainty when needed:

- "Based on the information we have so far..."
- "I do not want to overstate this before we have confirmed it."
- "The next useful step is to check..."
- "We have not confirmed the root cause yet, but we can confirm..."

## Evidence Gap Handling

If the evidence is thin but a reply is still useful:

- acknowledge the issue
- avoid diagnosis
- request the smallest useful next detail
- say what support can check next

If the evidence gap affects risk, billing, security, data, or a serious complaint, route to the appropriate readiness, evidence, or escalation workflow before drafting a firm answer.
