Use this reference when evidence is thin, the router must explain uncertainty, or the parent agent needs a compact list of Zendesk fields to inspect.

## Core ticket evidence

- Ticket ID or URL
- Requester and organisation
- Current status, priority, group, assignee, form, tags, and key custom fields
- Public replies and latest customer message
- Internal notes and agent observations
- Attachments, screenshots, logs, videos, or reproduction notes
- SLA state, ageing, reopen count, and recent follow-up cadence
- Product, site, plugin, plan, environment, or account context if present

## Impact and urgency evidence

- Number of affected users, team, site, or organisation
- Blocked workflow or business deadline
- Whether a workaround exists and whether the customer has confirmed it works
- Customer sentiment, frustration, escalation language, or executive visibility
- Security, privacy, compliance, billing, or data-integrity concern

## Pattern evidence

- Related tickets, linked problem tickets, merged tickets, side conversations, or known issue links
- Similar recent symptoms across other customers
- Same error text, affected component, recent release, or dependency
- Differences that suggest related but distinct issues

## Help Centre and knowledge evidence

- Existing public article, internal note, macro, or known workaround
- Whether the answer is stable and approved
- Whether the customer-facing boundary is clear
- Whether this is a new documentation gap or an update to existing content

## When evidence is missing

Name the smallest useful missing item instead of reopening broad discovery. Examples:

- latest public customer message
- internal notes from the handling agent
- confirmed impact or affected user count
- reproduction steps or timestamped screenshot
- related-ticket search result
- existing Help Centre article link
