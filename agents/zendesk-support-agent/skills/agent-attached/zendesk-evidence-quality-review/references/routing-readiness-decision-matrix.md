Use this reference before reviewing when the user request is ambiguous, when no reviewable artefact is supplied, or when evidence appears too thin for a safe QA pass.

The goal is to keep this skill as an after-output QA workflow and route upstream when the case needs evidence collection, triage, drafting, escalation creation, handoff preparation, knowledge creation, or backlog analysis first.

## Three-gate readiness check

Before reviewing, confirm all three gates are true.

1. **Artefact exists**: the user supplied a draft customer reply, investigation, escalation brief, handoff, backlog or trend summary, knowledge draft, or similar support artefact.
2. **Evidence exists**: the user supplied or the agent can access enough Zendesk evidence, pasted ticket content, support notes, or source material to check the artefact's claims.
3. **Task is QA**: the user wants the artefact checked, pressure-tested, edited safely, or reviewed before sharing.

If any gate fails, do not force a review. Route to the smallest upstream workflow and state the minimum missing input.

## Decision matrix

| Situation | Use this skill? | Route or response |
| --- | --- | --- |
| User provides a draft reply and ticket evidence, then asks whether it is safe to send | Yes | Review the draft. Use the customer reply template if helpful. |
| User provides a draft escalation and asks whether impact, urgency, and ask are supported | Yes | Review the escalation brief. Use the escalation template if helpful. |
| User provides a knowledge draft from a resolved case and asks whether it is publishable | Yes | Review the knowledge draft and check reusable evidence, caveats, and audience boundary. |
| User provides only a ticket ID or ticket URL and asks what to do | No | Route to `zendesk-triage-router` or `zendesk-evidence-collector`, depending on whether the need is routing or case facts. |
| User asks for a first customer reply but no draft exists | No | Route to `zendesk-draft-response` after evidence is available. |
| User asks for an escalation brief but no escalation draft exists | No | Route to `zendesk-customer-escalation` after evidence is available. |
| User asks whether there is enough evidence to create a reply, escalation, handoff, report, or article | No | Route to `zendesk-case-readiness-check`. |
| User asks to investigate root cause, reconstruct a timeline, or prove what happened | No | Route to `zendesk-evidence-collector`. |
| User asks to classify severity, priority, queue, owner, or next support workflow | No | Route to `zendesk-triage-router`. |
| User asks to prepare an internal handoff from case notes | No | Route to `zendesk-handoff-prep`. |
| User asks to turn a resolution into a new help-centre article | No | Route to `zendesk-create-knowledge`, or `zendesk-knowledge-candidate-review` if documentation worthiness is unclear. |
| User asks for a weekly support summary, queue health report, duplicate pattern, SLA, or ageing-risk analysis | No | Route to `zendesk-backlog-trend-analysis`. |
| User asks for both a draft and a review in one request | Not first | Create or route to the drafting workflow first; use this skill only as the final QA pass. |
| Connector access is unavailable but a reviewable draft exists | Maybe | Ask for the smallest missing evidence extract, then review only what is supported. |
| Evidence is a user-provided summary rather than ticket content | Maybe | Review cautiously, label findings as based on the supplied summary, and avoid treating the summary as confirmed ticket evidence. |

## Smallest missing evidence requests

Ask for the minimum input that unlocks the next workflow.

### Customer reply review

Ask for:

- The draft reply.
- The latest customer message or issue summary.
- Current confirmed status.
- Any approved commitments, exclusions, or next steps.

### Investigation review

Ask for:

- The draft investigation.
- Timeline of relevant events.
- Tests or checks already completed.
- Confirmed findings and unresolved questions.

### Escalation review

Ask for:

- The draft escalation.
- Customer/account impact.
- Attempted support steps.
- Current blocker.
- Exact ask for the escalation owner.

### Handoff review

Ask for:

- The draft handoff.
- Problem statement.
- What has already been tried.
- Evidence links or pasted extracts.
- Recommended next owner and next action.

### Backlog or trend summary review

Ask for:

- The draft report.
- Time window.
- Queue/filter scope.
- Counts and comparison basis.
- Inclusion/exclusion logic.

### Knowledge draft review

Ask for:

- The draft article or internal note.
- Resolution status.
- Confirmed workaround or limitation.
- Scope and exclusions.
- Intended audience.

## Routing response rule

When routing away, keep the response short and useful:

1. State that the request is not ready for evidence-quality review.
2. Name the smallest correct upstream workflow.
3. List the minimum missing evidence or artefact needed.
4. Do not produce a polished review or draft from unsupported facts.
