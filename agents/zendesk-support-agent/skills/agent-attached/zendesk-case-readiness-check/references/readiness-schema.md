Use this reference to keep classifications consistent across teammates and shared agents.

## Status values

### Ready

Use when the next deliverable can be completed safely from confirmed or clearly labelled evidence.

### Partially ready

Use when the direction is clear, but one missing item would materially improve safety, usefulness, or reduce avoidable rework.

### Not ready

Use when proceeding would require guessing, mislead the customer or receiving owner, or cause avoidable rework.

## Evidence classes

Use these labels mentally when comparing evidence. Include the label in the output only when it helps clarity.

- Confirmed Zendesk fact
- Help Centre or documented policy
- Customer claim
- Support observation
- Support assumption
- Secondary-system evidence
- Missing but obtainable evidence
- Missing and not currently obtainable evidence

## Classification checks

Before marking a case ready, confirm:

1. The target deliverable is explicit or safely inferred.
2. The minimum evidence threshold for that deliverable is met.
3. Any uncertainty can be framed honestly without weakening the next action.
4. The next step is support-operational and does not default to Linear, GitHub, Asana, or product planning.
