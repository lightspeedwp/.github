Ask only questions that materially affect routing, PRD readiness, technical brief quality, task planning or approval gates.

## Question rules

- Ask no more than five questions.
- Prefer three questions when possible.
- Do not ask a question if a safe default can be stated and tracked as an assumption.
- Ask about the next routing decision before later-stage detail.
- Mark unanswered questions as blockers, important gaps or later-stage gaps.

## Highest-value questions

1. What output does the team need next: evidence review, PRD, technical brief, task breakdown, GitHub issues, launch QA, content plan or full pack?
2. What is the approved source of truth for scope: brief, Figma, repo, live site, client email, Asana, Google Doc or something else?
3. What build type should be assumed: block theme, block theme plus plugin, hybrid conversion, WooCommerce, publishing/content platform, tourism platform, AI-readiness/chatbot or mixed?
4. Which sources are approved versus draft or unreviewed?
5. What is the next approval gate and who needs to sign it off?

## WordPress and Figma questions

- Is the work theme-only, plugin-only, or split across theme and plugin?
- Is Figma the approved design source or a directional prototype?
- Are there existing theme.json, token, pattern or component constraints?
- Are custom post types, taxonomies, fields or custom blocks required?
- Are there known plugin dependencies or exclusions?

## Launch and governance questions

- Are redirects, tracking, schema, accessibility, policy, privacy, claims or chatbot disclosures in scope?
- Is content approved, draft, missing or client-owned?
- Are there launch deadlines, phased releases or hard go/no-go gates?
- Should outputs be client-facing, internal or both?

## Estimation question

Ask this only when task planning or proposals are likely to follow:

- Which estimation model should later planning use: no estimates, T-shirt size, hours, sprint fit or complexity/risk only?
