## Purpose

Define the validation checks required for the Playwright Testing Agent asset pack so README files, examples, schemas, fixtures, profiles, prompts, and validation scripts stay structurally consistent and safe to reuse.

## Folder Coverage

Cover `examples/`, `schemas/`, `fixtures/`, `profiles/`, `prompts/`, `scripts/`, and `tests/`, and also validate root `README.md` plus linked validation assets under `tests/` and `scripts/`.

## Optional Coverage

Treat `memory/` and root `business-context.md` as optional. If they are present, validate them. If they are absent, validators should skip them cleanly rather than failing the whole pack.

## README Coverage

Verify the root `README.md` and each folder `README.md` use the expected section structure, document the real file inventory, and describe purpose, naming or usage rules, and maintenance expectations accurately.

## Required Folder Checks

Verify required folders exist, required files exist, file naming conventions are followed, and fail if `.schemas/` exists instead of `schemas/`.

## Routing Checks

Verify validation-facing docs do not weaken the mandatory PRD-to-test-pack route defined in the agent instructions. Routing guidance should stay consistent about requirement extraction, human-readable test cases first, and review-before-code expectations for that route.

## Skills Routing Checks

Verify that skills-routing guidance stays aligned with the real attached skill setup. If the instructions require a skill-first route, validation docs should name that expectation accurately, should not describe a missing or renamed skill, and should not assume a dedicated skills directory when none exists in the current pack.

## MCP Checks

Verify that MCP guidance stays aligned with the real attached app setup for LightSpeed Playwright MCP. Validation-facing docs and prompts should use the current MCP label, should describe it as browser automation and QA support rather than the default spec-generation or validation engine, and should not refer to a missing MCP file, folder, or unsupported action.

## Example File Checks

Verify required headings exist when enforced, heading order is correct, scenarios are specific enough to be useful, schema references are valid, and examples align with the paired output shape.

## Schema File Checks

Verify JSON parsing succeeds, required schema fields exist, strict required field coverage is present, schema filenames are valid, and every schema maps to at least one example unless it is explicitly exempted.

## Fixture And Profile Checks

Verify fixture and profile filenames follow current naming rules, remain grounded to their intended role, and are not confused with examples or validation assets.

## Prompt And Documentation Checks

Verify prompt files, README files, and validation docs use current folder names, current prompt-library names, and accurate maintenance guidance. This includes the umbrella validation-pack prompt plus the split validation prompts for scripts, docs/tests, and reference alignment.

## Link And Reference Checks

Verify internal file references resolve, example and schema references are valid, no broken relative links remain in the documented pack layer, and no invalid references point to a missing `.schemas/` path.

## Markdown Structure Checks

Verify required headings exist, heading order is correct, duplicate headings are rejected, placeholder text is detected, and required sections are not empty.

## Example And Schema Alignment Checks

Verify every required example points to the right schema, every schema has a matching example unless explicitly exempted, and stale template-path references are removed when no `templates/` folder exists.

## Source Priority Consistency Checks

Verify source-priority order only in files that currently declare it. If no current file-based source-priority reference exists, the validator should skip cleanly instead of failing on missing planned files.

## Business Context Checks

If `business-context.md` exists, verify it has the required headings and mentions WordPress, WooCommerce, the PRD-to-test workflow, approval gates, source priority, and that build-time research remains temporary context only.

## Starter Prompt Checks

Verify exactly six starter prompts exist, each has a title and prompt body, intents are not duplicated, prompts are not vague or too short, they align with the Playwright Testing Agent mission, and they do not ask for unsafe write actions without approval.

## How To Run

Run `bash scripts/validate-folder-schemas.sh` from the repository root after creating or updating validation-sensitive files. If optional folders or files such as `memory/` or `business-context.md` are absent, the relevant validators should report a clean skip.

## Expected Pass Criteria

All required folders and files exist, README coverage matches the real tree, naming and heading rules pass, routing wording stays aligned with the mandatory PRD-to-test-pack path, skills-routing guidance stays aligned with the real attached skill setup, MCP guidance stays aligned with the real LightSpeed Playwright MCP setup, schemas parse successfully, example-to-schema alignment is coherent, references resolve, prompt-library docs are current, starter prompts pass quality checks, and optional memory or business-context checks skip or pass appropriately.
