# GitHub Issue Drafting Rules

Create one GitHub issue per independently testable fix.

## Issue body structure

```markdown
## Summary

## Source finding

## Affected area

## Expected result

## Actual result

## Reproduction steps

## Evidence

## Acceptance criteria

## Retest steps

## Suggested labels

## Dependencies / blockers

## Related specialist route

## Internal LightSpeed notes
```

## Drafting rules

- Use action-oriented titles, e.g. `Fix mobile nav overlay on single tour template`.
- Do not bundle unrelated workstreams in one issue.
- Preserve original evidence and source references.
- Include exact affected URL/template/block/form when supplied.
- If reproduction is incomplete, draft a reproduction task rather than a fix.
- Include launch status and severity in the body, not only labels.
- Note dependencies such as design approval, copy approval, analytics access, plugin licence, redirect map or PR merge.

## Suggested labels

Use only relevant labels:

- `qa`
- `bug`
- `launch-blocker`
- `must-fix`
- `needs-reproduction`
- `accessibility`
- `responsive`
- `figma-parity`
- `block-theme`
- `block-plugin`
- `forms`
- `analytics`
- `seo`
- `schema`
- `content`
- `policy`
- `performance`
- `post-launch`
