## Project

- Client: Kinsta
- Type: Public-site evidence pass for potential WordPress rebuild estimate
- Current stage: Pre-estimate evidence summary completed on 11 May 2026
- Working estimate mode: Evidence pass before package routing
- Last public-site validation: 11 May 2026

## Sources Reviewed

- Live website homepage at <https://kinsta.com/
- Public pricing page at <https://kinsta.com/pricing/
- Public blog index at <https://kinsta.com/blog/
- Public docs index and docs listing at <https://kinsta.com/docs/ and <https://kinsta.com/?post_type=docs
- Public about and contact pages at <https://kinsta.com/about-us/ and <https://kinsta.com/contact-us/
- Public WordPress REST API endpoint at <https://kinsta.com/wp-json/
- Public search snapshots for multilingual sections and client success stories

## Confirmed Findings

- Public site is WordPress-backed because the public `/wp-json/` endpoint is available.
- Brand is Kinsta.
- Site is a marketing-led WordPress property for managed WordPress hosting, with pricing, sales CTAs, and trial/signup conversion paths.
- Public site includes a large blog, a documentation area, case studies / client success stories, changelog, resource center, and company pages.
- Public site shows a visible search function.
- Public site links to a separate logged-in customer area on `my.kinsta.com`.
- Public site is multilingual, with at least 10 language options visible in the footer and localized blog/docs sections in search snapshots.
- Contact flow exists and the public contact page shows a JavaScript-dependent contact form.

## Strong Routing Signals

- Not a standard brochure-site fit.
- Large existing content estate is likely, based on blog pagination, docs pagination, and multilingual public sections.
- Logged-in dashboard behavior exists in the wider customer journey, even if it may sit outside the marketing-site rebuild scope.
- Multiple connected web properties exist across `kinsta.com`, `my.kinsta.com`, `status.kinsta.com`, community, trust center, GitHub, and Sevalla links.

## Open Questions That Still Matter

- Is scope limited to the public marketing/content website, or does it also include `my.kinsta.com`, docs assistant behavior, community, status, or other connected properties?
- Which language versions are in scope for the rebuild at launch?
- Must the existing blog, docs, case studies, changelog, and legal-library content all migrate?
- Are there CRM, marketing automation, search, personalization, analytics, or translation integrations that must be preserved?
- Is the target delivery a WordPress rebuild only, or a broader architecture/program involving multiple properties and logged-in product surfaces?
