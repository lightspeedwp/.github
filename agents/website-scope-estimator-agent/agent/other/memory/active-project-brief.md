## Project

- Client: LightSpeedWP.Agency
- Type: Agency / service website rebuild or refresh
- Current stage: Routing
- Working estimate mode: Package-led website estimate
- Last evidence review: 18 May 2026

## Sources Reviewed

- Installed example context: `agent_files/docs/preview-validation/lightspeedwp-agency-example.md`
- Installed routing controls and package/commercial rules
- Live website homepage at `https://lightspeedwp.agency`
- Public GitHub repositories: `lightspeedwp/ls-theme` and `lightspeedwp/ls-plugin`

## Confirmed Findings

- The project is grounded in the installed LightSpeedWP.Agency preview-validation example context.
- The live site positions LightSpeed as a WordPress and WooCommerce agency with services, solutions, portfolio, blog, contact, search, newsletter signup, and consultation forms.
- The live site exposes solution areas for WordPress, WooCommerce, Tour Operators, and LSX products.
- The example context includes live, prototype, dev, Google Drive, Figma design-system, Figma Make, and GitHub references.
- The public theme and plugin repositories both exist and indicate custom implementation assets are part of the broader reference set.
- The currently reviewed live evidence still reads as a marketing-led agency website rather than a customer-facing ecommerce, booking, portal, or multilingual build.

## Routing Outcome

- Best-fit base package: WordPress Foundations Package
- Confidence: Moderate but provisional
- Commercial status: Provisional pending confirmation
- Reason: the confirmed live-site evidence reads as a standard agency/service website, while the broader reference stack suggests implementation complexity that could still escalate if those systems are in scope rather than reference-only
- Add-ons currently recommended: None yet from confirmed evidence alone

## Scope Risks Under Watch

- Plugin/theme repository involvement may indicate custom workflow or implementation complexity beyond a standard brochure site
- Design-system, prototype, and dev references may increase template, migration, or implementation complexity
- Fixed-fee eligibility is not yet confirmed because page/template count, integrations, staging expectations, and migration volume are still unknown

## Open Questions

- Is the target engagement a standard marketing-site rebuild, or does scope also include custom plugin/theme work?
- What is the in-scope page and template count across live, prototype, and dev references?
- What content must migrate from the current site?
- Which integrations, if any, must be retained or added?
- Is there any logged-in, membership, portal, multilingual, or headless requirement in the target scope?
- Which environment is the intended implementation baseline: live, prototype, or dev?
