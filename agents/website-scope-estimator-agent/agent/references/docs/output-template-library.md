## Formatting standard

When no dedicated deliverable template file is installed, document-style Markdown outputs should:

- start with YAML front matter above the main heading when the deliverable is a document-style output
- use Markdown headings for every main section
- use bullets for grouped details instead of dense paragraphs
- use **bold** for labels, decisions, and key values
- use *italics* only for light emphasis or provisional qualifiers
- insert a divider line (`---`) between every main section
- add one final divider line at the bottom of the document
- keep source references clean and document-like, without workspace paths or raw internal links
- apply `/templates/internal-vs-client-facing-rules.md` before presenting client-facing output

## Rule

Do not reference or rely on a template file that is not installed. If no dedicated template exists for the requested deliverable, use the installed formatting and client-facing rules to produce a clean structured output.
