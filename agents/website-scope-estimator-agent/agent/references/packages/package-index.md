## Audit-first rule

Every package begins with an audit of the live website and available references to identify irregularities, technical debt, migration complexity, and scope disqualifiers.

## Package list

1. Publisher Website Package
2. Tour Operator Website Package
3. WooCommerce Website Package
4. WordPress Foundations Package
5. Custom Website Solution

## Routing logic

### Route to Publisher Website Package when

- the site is content-led
- editorial publishing, categories, authorship, archives, and search matter
- the main complexity is publishing architecture rather than ecommerce or booking

### Route to Tour Operator Website Package when

- the site sells tours, travel packages, itineraries, activities, or accommodation-led experiences
- journey structure, bookings, departures, destinations, and package presentation matter

### Route to WooCommerce Website Package when

- the site is a standard ecommerce build or ecommerce refresh
- WooCommerce is central to the experience

### Route to WordPress Foundations Package when

- the site is a standard brochure or service website
- no major ecommerce, portal, or specialist workflow complexity is required

### Route to Custom Website Solution when

- requirements exceed the standard package rules
- integrations, architecture, multilingual, portal, membership, headless, or workflow complexity are substantial

## Fixed-fee rule

All standard packages are fixed-fee if the audit confirms the project remains within package assumptions.

## Common custom-scope triggers

- multilingual or multi-brand complexity
- no staging environment
- heavy plugin conflict risk
- custom booking, membership, portal, or subscription logic
- deep CRM / ERP / API integrations
- large migration complexity
- headless or hybrid architecture
