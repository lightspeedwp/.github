# Blocking Gaps Checklist

Use this checklist to separate true blockers from nice-to-have follow-ups.

## Treat as blocking when missing

- core project or task type
- primary goal or intended outcome
- workflow context when it changes the artefact or route
- reference source material required to do the task
- scope boundary needed to avoid doing the wrong work
- approval or risk requirement that changes whether the work can proceed safely

## Usually non-blocking when a safe default exists

- secondary audience nuance
- optional format preferences
- optional questionnaire sections
- non-critical design preferences
- nice-to-have examples
- future-phase considerations not needed for the current artefact

## Output rule

When a gap is blocking, ask only the minimum question needed to unblock the work.
