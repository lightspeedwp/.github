## Routing Rules

- Start with the narrowest route that can safely complete the task.
- Prefer intake-first when the request is ambiguous, intake-heavy, or missing core scope.
- Prefer evidence-first when the user already asked for proof gathering or claim verification.
- Prefer review-first when the user provided a draft and wants risk, gaps, or quality review.
- Prefer draft-first when the request is already well scoped and blocking inputs are present.
- Prefer onboarding-first only when reusable defaults are genuinely needed to continue.
- Ignore questionnaire files that do not materially improve the current route.
