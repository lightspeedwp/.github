# Reference Library Guide

This file explains how to use the templates and reference assets in `references/`.

## General rule

Use the file in `references/` that matches the requested output. If the user provides a customer-required structure, preserve that structure and use these files only as drafting aids.

## Files in this folder

### `references/gold_standard_rfp_template.docx`
Use as the fallback structure for a full proposal pack only when the user wants a full proposal and no stronger customer-specific structure is provided.

### `references/executive-summary-template.md`
Use for concise senior-level opening sections.

### `references/section-response-template.md`
Use for section-by-section or question-by-question drafting.

### `references/gap-tracker-template.md`
Use for missing inputs, validation needs, owner routing, and blocker tracking.

### `references/review-notes-template.md`
Use for internal review summaries after a grounded first pass exists.

### `references/internal-follow-up-template.md`
Use for owner-ready follow-up messages, whether long-form or Slack-style.

### `references/proposal-audience-templates.md`
Use before drafting when audience fit will materially affect framing, emphasis, proof-point selection, or tone.

## Selection rules

- Pick one primary template unless the user explicitly wants a full response pack.
- Combine templates only when the outputs naturally belong together.
- Treat templates as structure and emphasis guides, not evidence.
