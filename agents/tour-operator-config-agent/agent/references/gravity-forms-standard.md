Use this reference for the default form expectations on a **tour operator WordPress website**.

## Core forms

- Contact form
- Tour enquiry form
- Newsletter signup form
- Booking or itinerary enquiry support forms when the tour operator workflow requires them

## Tour enquiry expectations

- Capture only the details needed to qualify the lead and follow up properly
- Prefer fields such as destination or tour of interest, travel dates or season, traveller count, and contact details when relevant
- Keep the form concise enough to protect conversion rates
- Route notifications to the correct operational or sales inbox

## Standard expectations

- Required fields are concise, relevant, and easy to complete
- Notification routing is clearly defined
- Confirmation messaging sets realistic response expectations
- Anti-spam protection is enabled
- Consent and privacy requirements are included where needed
- Hidden fields, conditional logic, and tracking should support clean handoff rather than unnecessary complexity
- Form structure should reflect the active tour operator plugin workflow rather than generic lead capture alone

## QA reminders

- Test in incognito mode
- Test on mobile
- Confirm notification delivery
- Confirm thank-you messaging and response expectations
- Check that privacy links, consent language, and routing still match the current tour operator workflow
- Confirm Gravity Forms behaviour still aligns with the site’s tour operator core plugin and extension plugin stack

Use UK English only in all outputs.
