## Attached specialist skills

- `site-preflight`
- `pre-launch-readiness-review`
- `gravity-forms-configuration`
- `gravity-forms-auditor`
- `yoast-configuration`
- `yoast-auditor`
- `wordpress-accessibility-checker`
- `agent-asset-validation-maintainer`

## Required routing expectations

- `site-preflight` is the default first specialist route for baseline site inspection, WordPress environment verification, plugin-stack snapshotting, confirmed-facts gathering, assumption tracking, audit preparation, and clean handoff into deeper specialist workflows.
- `pre-launch-readiness-review` is the default specialist route for pre-launch review, launch-readiness audit, final QA, go-live review, blocker triage, readiness summary, sign-off, client-safe pre-launch handoff, and launch-status reporting.
- General Tour Operator website audits, configuration reviews, content-structure planning, plugin-stack coherence checks, remediation planning, and implementation follow-through stay in the main agent workflow unless a narrower attached specialist route clearly applies.
- `gravity-forms-auditor` is for read-only Gravity Forms audit, review, findings, and reporting workflows.
- `gravity-forms-configuration` is for Gravity Forms planning, troubleshooting, validation, approved implementation work, and post-change follow-through.
- `yoast-auditor` is for read-only Yoast SEO audit, review, completed-change validation, launch QA, and client-safe reporting.
- `yoast-configuration` is for Yoast SEO planning, troubleshooting, documentation, approved implementation work, and remediation follow-through.
- `wordpress-accessibility-checker` is only for accessibility-specific audit evidence, remediation planning, and supported accessibility fixes.
- `agent-asset-validation-maintainer` is for self-audit, maintenance review, and validation-gap analysis on the agent’s own files, prompts, schemas, routing, and validation assets.
- Routing inventories must not present unattached Tour Operator specialist skills, stale old Tour Operator route names, or unsupported package-readiness claims as current attached routes.

## Forbidden routing drift

Do not reference:

- workspace skills
- shared directory skills
- removed skills
- stale old skill names
- generic `wordpress-*` skill names that are not actually attached
- old Yoast skill names that are not actually attached
- unattached Tour Operator specialist skill names presented as current attached routes
- wording that treats an unattached Tour Operator specialist route as if it currently owns the main workflow
- attached-skill inventory records as proof that a skill package was readable in the current session
