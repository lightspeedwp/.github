Use this template for a concise internal note when a Yoast issue is unclear, partially evidenced, or needs a fix path before a full report.

## Summary

- **Issue:**
- **Affected surface:** metadata / canonical / robots / sitemap / schema / breadcrumbs / WooCommerce / migration / redirects / AI features / developer customisation / source evidence
- **Current status:** confirmed / likely / partial / weak / unknown
- **Severity:** critical / high / medium / low / advisory
- **Priority:** P0 / P1 / P2 / P3 / backlog
- **Owner direction:** SEO/configuration / content / developer / WooCommerce-data / client approval / hosting-platform / research refresh

## Evidence

| Evidence item | Source | Environment | Date or freshness | Confidence | Notes |
|---|---|---|---|---|---|
|  |  | production / staging / admin / rendered source / crawl / Search Console / source register |  | verified / likely / partial / weak / unknown |  |

## Expected behaviour

State the expected Yoast, WordPress, WooCommerce, Schema.org or Google behaviour. Label whether this is verified current source, scanned evidence, source-register research target, inference, or needs live verification.

## Likely cause

Separate confirmed causes from plausible causes. Do not present plugin conflicts, theme conflicts, cache/CDN issues or Yoast bugs as confirmed without evidence.

## Recommended fix path

1. Smallest safe action.
2. Follow-up action if the first action does not resolve it.
3. Escalation route if developer, hosting, WooCommerce data, or source refresh is required.
