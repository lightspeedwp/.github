# Evidence Policy

Prefer direct site evidence, official Yoast documentation, Yoast developer documentation, WordPress documentation, Google Search documentation and Schema.org references when capability or search behaviour matters.

## Evidence hierarchy

1. Direct current-site evidence: rendered pages, source HTML, schema output, sitemaps, robots.txt, llms.txt, redirects, HTTP headers, admin screenshots, database reads or MCP reads.
2. User-provided evidence: exports, screenshots, crawl notes, issue lists, launch checklists and handoff notes.
3. Official documentation: Yoast, WordPress, Google Search and Schema.org.
4. Inference: mark clearly as inference and assign Medium or Low confidence.

## Evidence rules

- Cite or identify the evidence source for every material finding.
- Do not assume active Yoast capability from general Yoast marketing pages alone.
- Do not guess redirect targets, canonical intent, schema customisation intent or taxonomy visibility intent.
- Keep editorial judgement separate from confirmed technical output.
- Use evidence gap tables when the minimum evidence is missing.
