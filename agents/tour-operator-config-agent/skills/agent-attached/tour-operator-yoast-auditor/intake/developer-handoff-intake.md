# Developer Handoff Intake

Use this when audit findings need to become implementation-safe developer notes.

## Required fields

- Problem.
- Confirmed evidence.
- Affected URLs or templates.
- Expected output.
- Suggested implementation route.
- Risk if unfixed.
- Dependencies.
- QA steps.
- Confidence.
- Owner and next route.

## Developer handoff guardrails

- Do not prescribe code when the evidence only supports a high-level issue.
- Do not edit Yoast generated tables directly.
- Do not guess redirect destinations.
- Do not assume a specific plugin or theme architecture without repository, admin or MCP evidence.
- Separate content/editorial actions from developer actions.
