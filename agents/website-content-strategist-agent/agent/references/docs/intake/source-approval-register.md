## Purpose

This file is the current-state working register for deciding which sources are safe to reuse during intake, drafting, review, claim handling, and Memory promotion.

Use it to distinguish between:

- approved sources that can safely inform reusable outputs
- present but unapproved sources that can inform questions or provisional intake only
- risky or restricted sources that require review before reuse
- sources that should not be used for public-facing claims or durable memory

This register works with the evidence-token schema. Evidence tokens capture extracted values. This register records whether the underlying source is actually approved for operational reuse.

---

## Core rules

- A source being available does not mean it is approved.
- Public URLs, screenshots, rough notes, questionnaires, repos, and uploaded files are not automatically approved for reuse.
- Questionnaire files are intake references, not approved project truth by default.
- Use unapproved sources for intake guidance, blocker detection, and follow-up questions, not as durable truth.
- Only approved or explicitly confirmed sources should support durable Memory promotion or high-confidence public-facing drafting.
- If approval status is unclear and it matters, ask one focused question instead of stalling broadly.

Recommended focused question:

**Is this source approved for reuse in the working output, or should I treat it as reference-only for intake?**

---

## Approval statuses

| Status | Meaning | Safe use |
|---|---|---|
| approved | The source is explicitly approved for operational reuse. | Can support drafting, structured outputs, and confirmed-memory candidates where appropriate. |
| approved_with_limits | The source is approved, but only within stated constraints. | Can be used only for the allowed scope, audience, workflow, or output type. |
| reference_only | The source is useful for orientation or intake, but not approved as operational truth. | Can support questions, routing, and provisional defaults only. |
| pending_review | Approval is not yet known or is awaiting owner review. | Use only for provisional intake and clearly flagged working assumptions. |
| restricted | The source contains sensitive, confidential, legal, privacy, or otherwise controlled material. | Do not reuse outside the approved boundary without review. |
| unsupported | The source should not be relied on for this workflow or output. | Do not use for drafting, claims, approvals, or durable memory. |

---

## Register schema

Use each source entry in this structure.

| Field | Purpose |
|---|---|
| Source label | Human-readable name for the source |
| Source type | URL, document, questionnaire, design file, screenshot, repository, brief, policy, or other |
| Source locator | Stable link, filename, path, or identifying reference |
| Scope covered | What part of the workflow or project the source informs |
| Approval status | Current approval status from the allowed list |
| Approved for | What it is safe to support |
| Not approved for | What it must not be used to support |
| Approval owner | Person or role responsible for approval |
| Verification basis | User confirmation, approved source, inferred only, policy-controlled, etc. |
| Claim-safe | Yes, no, or needs review |
| Memory-safe | Yes, no, or needs review |
| Notes | Short explanation of limits, uncertainty, or review dependency |

```md
## Source: <source label>

- Source type: <source type>
- Source locator: <stable locator>
- Scope covered: <project / page / section / policy / workflow>

- Approved for:
  - <allowed use>
- Not approved for:
  - <disallowed use>
- Approval owner: <person / role / unknown>
- Verification basis: <user confirmed / approved source / inferred / review required>
- Claim-safe: <yes | no | needs review>
- Memory-safe: <yes | no | needs review>
- Notes:
  - <key caveat or next review action>
```

## Source-type guidance

### Approved brief or strategy document

Typical status:

- `approved` or `approved_with_limits`

Usually safe for:

- project goals
- audience direction
- approved messaging priorities
- scope boundaries
- confirmed source-of-truth references

Still review before using for:

- quantified claims
- legal promises
- guarantees
- time-sensitive facts

### Questionnaire file

Typical status:

- `reference_only`

Usually safe for:

- intake field discovery
- routing context
- missing-information detection
- smart question generation
- provisional defaults during current intake

Not safe by default for:

- confirmed project memory
- factual public-facing claims
- approval-sensitive commitments
- legal or policy conclusions

### Public URL

Typical status:

- `reference_only` or `pending_review`

Usually safe for:

- orientation
- extraction of likely messaging, audience, and offer signals
- comparison against other provided sources

Not safe by default for:

- claim approval
- durable memory
- controlled policy or governance interpretation

### Screenshot or design file

Typical status:

- `reference_only` or `approved_with_limits`

Usually safe for:

- design direction
- hierarchy
- content structure cues
- component or section planning

Not safe by default for:

- legal wording
- approved proof claims
- approval ownership assumptions

### Repository

Typical status:

- `reference_only`, `approved_with_limits`, or `approved`

Usually safe for:

- implementation context
- structural content references
- technical requirements
- integration cues

Review before using for:

- approval assumptions
- current truth of marketing copy
- proof claims visible in code or seeded content

### Policy or legal source

Typical status:

- `restricted` or `approved_with_limits`

Usually safe for:

- controlled policy interpretation
- exclusions
- privacy handling constraints
- compliance-related routing

Not safe for unrestricted reuse unless:

- the right owner has approved the intended usage

## Claim and memory interaction rules

### Claim-safe rules

Mark a source as **Claim-safe: yes** only when:

- the source is approved or approved with clear limits
- the factual content is appropriate for public reuse
- any quantified, comparative, testimonial, guarantee, ranking, pricing, ROI, performance, or outcome claim is supported

Mark **Claim-safe: needs review** when:

- the source contains factual claims but approval is incomplete
- the source is public or visible but not explicitly approved
- the source contains questionnaire-derived or inferred claims

Mark **Claim-safe: no** when:

- the source is unsupported, restricted, or clearly unapproved for public factual use

### Memory-safe rules

Mark a source as **Memory-safe: yes** only when:

- the source is approved for reuse
- the values drawn from it are stable enough to help future related work
- the values are suitable for confirmed reusable project memory

Mark **Memory-safe: needs review** when:

- the source is useful but approval is incomplete
- the source may support memory candidates but not confirmed memory yet

Mark **Memory-safe: no** when:

- the source is reference-only, restricted, unsupported, or too unstable for durable reuse

## Review triggers

Escalate or pause for source review when:

- a source may be reused in public-facing output but approval is unclear
- a source contains regulated, legal, privacy, medical, financial, safety, or high-trust content
- a source contains statistics, guarantees, comparisons, rankings, awards, testimonials, or case-study claims
- a source may shape durable project memory
- a source appears to conflict with a stronger approved authority
