## `lightspeed-project-context.md`

```md
# LightSpeed project context

## Project
- Project name: Safari Horizons website refresh
- Client: Safari Horizons
- Website or workstream: Main marketing site
- Primary audience: High-intent safari travellers comparing premium tours
- Core goal: Clarify offer positioning and improve enquiry conversion

## Current stage
- Current stage: Source review and intake complete
- Current focus: Service-page structure and homepage messaging
- Last confirmed progress: Approved site-map draft and source pack reviewed
- Best next step: Draft the homepage and core tour-category pages

## Approved sources
- Primary approved sources: Discovery brief, current website copy deck, stakeholder notes
- Secondary approved sources: Figma homepage concept, competitor comparison notes
- Source gaps still affecting work: No approved testimonials shortlist yet

## Authority order
1. Discovery brief
2. Approved copy deck
3. Stakeholder notes
4. Figma concept

## Key constraints
- Keep tone premium but not luxury-cliche
- Avoid unsupported wildlife-guarantee claims
- CTA should prioritise itinerary enquiry over generic contact

## Current decisions
- Confirmed decision: Homepage should lead with tailor-made safari planning
- Confirmed decision: Trust signals should sit above the fold
- Open decision still affecting work: Whether to separate family and honeymoon safari journeys

## Last updated
- Date: 2026-05-15
- Reason for update: Intake completed and source review confirmed
```

## `lightspeed-preferences.md`

```md
# LightSpeed project preferences

## Output structure defaults
- Preferred default structure: Summary, key findings, recommended next step, draft output
- Preferred heading style: Sentence case Markdown headings
- Preferred summary style: Short prose summary before bullets
- Preferred ending style: One clear next step

## Metadata defaults
- Metadata fields to include: Project, stage, source status, review status
- Versioning preference: v1.0 for first formal draft
- Divider-line preference: Use horizontal rules before each main section
- Traceability notes: Note approved vs unapproved claims where relevant

## Review framing defaults
- Preferred review depth: Medium-depth review with clear priorities
- Preferred way to show blockers: Separate blocker section with impact noted
- Preferred way to show gaps: Distinguish source gaps from approval gaps
- Preferred way to show next step: Single recommended next action

## Drafting conventions
- Tone defaults: Clear, commercially confident, practical
- CTA style defaults: Specific consultation or enquiry CTAs
- Proof or evidence standard: Flag unsupported claims explicitly
- Internal linking preference: Suggest internal links where they improve routing
- Section-length preference: Keep sections scannable and concise

## Last updated
- Date: 2026-05-15
- Reason for update: Established default project conventions
```

## `user-preferences.md`

```md
# User preferences

## Spelling and style
- Preferred English style: UK English
- Preferred punctuation or style notes: Use clean editorial punctuation, avoid em dashes where a comma works
- Terms or spellings to prefer: organisation, prioritise, labelled
- Terms or spellings to avoid: overly salesy hype phrases

## Review preferences
- Preferred review depth: Practical mid-depth review
- Preferred level of detail: Enough detail to act without over-explaining
- Preferred way to show blockers: Clear blockers section with owner or dependency when known
- Preferred way to show assumptions: Short assumptions note only when necessary

## Formatting preferences
- Preferred section order: Summary first, then findings, then next step
- Preferred heading style: Clean Markdown headings
- Preferred use of bullets vs paragraphs: Short prose summary plus grouped bullets
- Preferred metadata style: Compact metadata block when useful
- Preferred divider-line usage: Use divider lines in polished document outputs

## Writing preferences
- Preferred tone: Clear, direct, collaborative
- Preferred phrasing to avoid: grandiose agency jargon
- Preferred clarity level: High clarity, low fluff
- Preferred CTA wording style: Specific next-step wording

## Last updated
- Date: 2026-05-15
- Reason for update: Captured standing user preferences
```

# LightSpeed open items

## Missing inputs
- Approved testimonial shortlist
- Final FAQ source list
- Confirmed lead magnet CTA target

## Approvals needed
- Approval needed: Homepage hero positioning
  - Owner: Client lead
  - Status: Pending
- Approval needed: Testimonial usage
  - Owner: Marketing stakeholder
  - Status: Awaiting shortlist

## Evidence gaps
- No approved conversion stats yet
- No confirmed proof for "most tailored safari planning" wording

## Risks
- Risk: Overclaiming premium differentiation without evidence
  - Impact: Trust and compliance risk
  - Mitigation: Use restrained proof language until evidence is approved
- Risk: CTA route may be too generic
  - Impact: Lower enquiry conversion
  - Mitigation: Confirm itinerary-enquiry CTA destination

## Pending decisions
- Decision needed: Separate journey pages by audience or keep one category page
  - Options: Single category page / split by traveller type
  - Recommended direction: Keep one category page until content volume justifies a split

## Last updated
- Date: 2026-05-15
- Reason for update: Captured unresolved blockers and decisions
