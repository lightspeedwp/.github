Use this guide when storing reusable brand voice and tone defaults in Memory.

## What to save

Save only stable voice and tone defaults that should shape future related content work, such as:

- brand personality summary
- core tone pillars
- wording to prefer
- wording to avoid
- trust and proof sensitivity notes
- tone shifts by page type, audience intent, or funnel stage
- voice constraints for policy, support, sales, editorial, and responder content

## What not to save

Do not save:

- one-off copy experiments
- rough adjective lists that have not been agreed
- temporary campaign slogans unless they will recur
- speculative style ideas
- unconfirmed internal opinions about tone

## Suggested Memory location

Use `lightspeed-preferences.md` for project-level voice defaults and `user-preferences.md` only for the user's own standing style preferences.

## Validation rule of thumb

A saved voice value should be:

- confirmed or explicitly approved
- reusable across future related work
- specific enough to guide drafting and review
- concise enough to stay maintainable
