# Examples folder

## Purpose
This folder stores structural examples that demonstrate what compliant outputs should look like.

## Naming conventions
- Use lowercase kebab-case names ending in `-example.md`.
- Keep one canonical example per template family unless a second example is materially different.
- Examples should demonstrate structure, not reusable client copy.

## File outline
- `review-output-example.md` — structural example for review-style outputs.
