# Website Pages Builder

## When to use this skill

Use this skill when the main deliverable is a standard website page or page-level structure.

This skill is strategy-first. It should turn approved inputs, strategic defaults, and specialist intake outputs into page structures or drafts that support the wider site objective.

## Core page requirements

Every website page output must account for these planning layers before it is treated as complete:

1. page purpose and conversion role
2. approved CTA route
3. proof or stats handling when relevant
4. exactly five FAQ planning slots
5. claim-register handoff for claim-sensitive FAQ answers or stats

If the page template does not already show these layers clearly, add them in the working output instead of silently skipping them.

## Memory state

Use Memory only for reusable page-work defaults that should affect future related page work.

Save:

- standard page type for the project
- preferred page template family
- approved CTA model
- recurring section defaults
- known page-level proof or approval sensitivities
- repeated internal-linking conventions
- recurring FAQ themes when they are stable across page families

Do not save:

- draft copy variants
- temporary headline options
- unresolved speculative messaging
- unsupported proof claims
- one-off FAQ answers that have not been approved for reuse

## Workflow

1. Identify the page type.
2. Match it to the correct page-type template.
3. Check the page's role in the wider user flow and the site's overall conversion objective.
4. Check source authority, claim sensitivity, CTA route, and required sections.
5. Define exactly five useful FAQ planning slots for the page, even if the final published page may hide or relocate them.
6. If the page depends on stats, quantified proof, trust figures, or performance numbers, require structured stats intake before treating those numbers as publish-ready.
7. Route all claim-sensitive FAQ answers and all claim-bearing stats into the claim register before final drafting or publication.
8. Draft or structure the page according to the template.
9. Flag missing proof, missing approvals, unsupported FAQ answers, risky stats, or routing uncertainty clearly.
10. Hand off to claim validation or formatting validation when needed.

## FAQ rules

- Every page must support exactly five FAQ planning slots.
- If the page should not visibly publish FAQs, still define the five most useful questions in the planning layer and mark them as `hidden`, `deferred`, or `answered elsewhere`.
- FAQ slots should prioritise real objections, route-selection questions, trust questions, process questions, or decision-stage concerns.
- For each FAQ, account for:
  - question
  - answer summary
  - internal link if useful
  - publish status
  - claim-sensitive yes or no
  - claim-register action

## Stats and proof rules

- Use stats only when they support trust, proof, orientation, or conversion.
- Do not add decorative numbers.
- For each stat or proof figure, account for:
  - figure
  - title
  - description
  - evidence source
  - approval status
  - claim-register action
- If a number is unsupported, rewrite it as safer non-numeric proof or mark it as `evidence required`.

## Output

Return a clean page structure or draft using the matched template shape, plus the required FAQ planning layer and stats/proof layer when relevant.
