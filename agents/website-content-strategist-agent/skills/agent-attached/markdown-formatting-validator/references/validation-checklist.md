# Validation checklist

- Correct output type chosen
- YAML frontmatter present when required by the output type
- One `#` main heading present
- Required sections present
- Heading depth consistent
- Divider usage consistent before every main section after the first
- Final divider line present at the bottom of the document
- Metadata block compact and relevant
- No duplicated headings
- No rough internal notes in final copy
- Label style consistent
- UK English consistent
- CTA wording aligned with output purpose
- For intake-style review outputs, exact section order present
- Dedicated `## Approval and readiness state` section present in the required position
- Readiness wording uses exact `Current state:` and `Limit:` labels
- `Current state:` uses one allowed readiness value only, with no extra explanatory wording on that line
- Material gaps in `## Missing intake` use the exact required bullet pattern
- Divider line present before every required `##` section after the first
- No internal path, workspace path, or memory path wording remains in final review copy
