# Conversion Goal Strategist

## When to use this skill

Use this skill when the request depends on understanding audience intent, user flows, conversion priorities, or how each page or content asset should contribute to a wider site objective.

Typical use cases:

- define site-wide conversion objectives before content drafting
- map how key pages contribute to lead generation, product discovery, booking, signup, or enquiry goals
- identify user flows by audience type or funnel stage
- clarify page goals for homepage, service pages, about pages, product pages, newsletters, forms, and responder flows
- align content recommendations with measurable visitor actions

Do not use this skill when page goals and user flows are already clearly defined and the task is only normal drafting or packaging.

## Core rule

This is a strategic intake area. Do not jump from vague goals to final conversion logic.

When the current answers are not strong enough to define page contribution, CTA logic, and user flow priorities, keep asking focused follow-up questions until there is enough information to define:

- the primary audience and intent
- the primary conversion goal
- the secondary or fallback action
- the key user-flow steps
- the role of the page or asset in the wider site journey

Use smart defaults to reduce friction, but do not silently choose the final conversion model for the user.

## Guided intake workflow

1. Identify the scope: full website, page family, single page, newsletter flow, or form/responder flow.
2. Collect the smallest useful strategic foundation first:
   - primary audience
   - main user intent
   - primary conversion goal
   - CTA destination or next action
   - main friction or trust barrier
3. If any of those are unclear, present compact options and ask the user to choose or refine them.
4. Map the main audience flows and the role of each page or content asset in those flows.
5. Define page-level conversion goals and how they support the overall site objective.
6. Note dependencies such as proof, trust, FAQs, forms, policy content, or routing clarity.
7. Do not move to final guidance until the core conversion logic is strong enough to support real content decisions.

## Smart defaults and option-led guidance

When the user is unsure, present 3 to 5 concise options drawn from `references/conversion-goal-options.md` and recommend the closest working default based on the scenario.

Use recommendation language like:

- "The strongest working default looks like..."
- "If the page is earlier-stage, use..."
- "If the user is closer to a decision, use..."

Good option groups include:

- primary audience type
- user intent type
- primary conversion action
- fallback conversion action
- CTA model
- funnel stage
- main friction type

For common site scenarios, use `references/conversion-goal-scenario-defaults.md` to suggest a starting direction, but always leave the final choice with the user.

## Question discipline

Ask more questions only when the missing answer changes structure, CTA logic, or how the page should convert.

Prioritise questions in this order:

1. primary audience
2. main user intent
3. primary conversion goal
4. fallback action if the user is not ready yet
5. CTA destination or routing model
6. main friction or trust barrier
7. page contribution within the wider site journey

If the user answers vaguely, turn that into concise options and ask for a choice.

## Memory use

When conversion defaults are confirmed, store them in Memory using the project files described in the agent instructions.

Persist only durable strategic defaults that should shape future related work, such as:

- primary audience segments
- primary and secondary conversion goals
- user-flow priorities
- CTA model and routing model
- page-role definitions by page type
- funnel-stage notes that affect drafting and review
- main friction and trust notes that recur across the project

Use project Memory for project-level conversion defaults and update existing values instead of creating conflicting duplicates.

Do not store tentative growth ideas, unconfirmed metrics targets, or one-off campaign experiments as durable Memory unless the user confirms they should recur.

## Completion threshold

Do not treat conversion intake as complete until you have enough to define:

- primary audience
- primary conversion goal
- fallback or secondary action
- CTA route or next action
- basic page or asset role in the user flow

If those pieces are not yet clear, ask another focused question.

## Output

Return these sections when relevant:

- Conversion objective summary
- Primary audiences and user intent
- User-flow map
- Page or asset contribution to conversion
- Friction points and dependencies
- Working defaults to store in Memory
- Recommended next step for content planning or drafting
