## Purpose

Use this folder for recurring maintenance prompts that help maintain and improve the WooCommerce Configuration Agent itself.

These files are not delivery workflows for end-user WooCommerce work. They are reusable maintainer prompts for auditing, repairing, refreshing, aligning, or tightening the agent's own instructions, routing layer, validation layer, README layer, app-usage guidance, connector guidance, schema-coverage guidance, source snapshots, and prompt library.

## Current folder position in the agent structure

Treat the current attached maintenance structure as:

- `prompts/` — recurring maintainer prompts for agent-upkeep work
- `references/` — durable standards, conventions, and maintenance workflows
- `schemas/` — structured validation and output contracts
- `scripts/` — runnable validators, validation runners, and helper scripts
- `tests/` — QA sources, scenario coverage, regression checklists, and validation-support material

This folder supports the maintenance workflow. It does not replace the main instructions, attached local skills, validator scripts, or durable reference files.

## Naming conventions

Use practical, maintenance-friendly names that describe both the subject and the type of pass:

- `<subject>-prompt.md` for a single focused recurring prompt
- `<subject>-audit-prompt.md` for audit-only or validation-first passes
- `<subject>-validation-prompt.md` for validation-first checks that report issues before repair
- `<subject>-cleanup-prompt.md` for broader consistency cleanups
- `<subject>-repair-prompt.md` for implementation passes that repair issues found elsewhere
- `<subject>-refresh-prompt.md` for documentation refresh or inventory-alignment work
- `<subject>-tightening-prompt.md` for validation-pack or standards-hardening work
- `<subject>-alignment-prompt.md` for focused alignment work across instructions, references, prompts, or validation notes

Keep names explicit. Prefer subject-first naming over generic names such as `cleanup.md` or `prompt1.md`.

## How these files should work

Each recurring prompt in this folder should:

1. State its purpose clearly.
2. Define whether it is a validation, audit, repair, refresh, cleanup, tightening, or alignment pass.
3. Treat the current attached local skills and current attached file tree as source of truth when relevant.
4. Stay scoped to agent-maintenance work unless the prompt explicitly says otherwise.
5. Describe concrete deliverables.
6. Include constraints so the pass stays conservative and does not invent skills, folders, workflows, apps, or unsupported structure.

When a prompt depends on the current local skill set, it should name those local skills explicitly instead of using vague wording such as "use the appropriate skill."

When a prompt depends on the current attached app set, it should keep that app list grounded to the attached app inventory and connected-app guidance.

When a prompt is part of a paired workflow, the validation or audit prompt should usually run first, followed by the repair prompt.

## Canonical role rules

- Treat this folder as the recurring prompt library for maintaining the agent itself.
- Keep prompt wording aligned with the current main instructions, routed local skill set, attached app set, and attached file structure.
- Update prompt inventories when prompt files are added, removed, or renamed.
- Prefer replacing stale wording over layering duplicate instructions into multiple prompt files.
- If a prompt enumerates the current local skills, keep that list aligned with the actually attached local skills.
- If a prompt enumerates the current attached apps or maintainer references, keep those lists aligned with the current attached configuration.
- Keep maintenance work in this folder separate from normal WooCommerce delivery routes.
