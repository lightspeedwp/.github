# Example: bilingual contact form

Use this example when a publication, ecommerce site, or regional business needs a contact form in more than one language.

## Goal

Create or review a form setup that keeps language-specific labels, confirmations, consent wording, and admin routing maintainable.

## Recommended stance

- Prefer separate language variants when consent wording, admin routing, or CRM/list destinations differ.
- Keep field purpose consistent across variants so reporting remains comparable.
- Include the submitted language/source page in admin notifications.
- Do not overwrite a live English form with translated labels; duplicate or draft a variant first.
- Treat consent translation as approval-required.

## Suggested fields

1. Name
2. Email
3. Phone optional
4. Preferred language
5. Enquiry type
6. Message
7. Consent

## Confirmation

Use a language-matched thank-you message with a realistic next step.

## Notifications

- Admin notification includes source page, submitted language, enquiry type, and Reply-To.
- User autoresponder matches the submitted form language.

## Test cases

- Submit each language variant.
- Confirm visible labels, validation messages, confirmation, notifications, and admin routing.
- Confirm consent entry records the correct language-specific wording.
