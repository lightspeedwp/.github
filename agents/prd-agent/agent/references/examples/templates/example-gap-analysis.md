# Gap analysis

## Current evidence state

The project has enough material to understand the general redesign intent, but not enough validated evidence to trust a full PRD or estimate yet.

## Priority gaps

- Editorial workflow priorities are not confirmed.
- Accessibility baseline is missing.
- Analytics baseline for content discovery is missing.
- Source-of-truth design direction is only partially validated.
- Technical constraints from the current theme architecture are not yet fully reviewed.

## Why each gap matters

- Editorial workflow priorities determine the real operational scope.
- Accessibility baseline affects compliance risk and implementation effort.
- Analytics baseline is needed to define success criteria for discoverability improvements.
- Design ambiguity can create false certainty in requirements and technical planning.
- Theme constraints may materially change implementation strategy and delivery effort.

## Risk of proceeding without resolution

Proceeding now would likely produce a PRD that looks complete but rests on weak operational evidence, and any estimate derived from it would carry avoidable uncertainty.

## Fastest resolution path

- Confirm editorial workflow pain points with stakeholders.
- Run or collect an accessibility baseline review.
- Gather current analytics for content discovery and navigation behaviour.
- Confirm the current design source of truth.
- Review the existing repository and theme architecture before implementation planning.

## Recommended next planning step

Create a planning brief only after the missing workflow, baseline, design, and technical evidence is collected and normalised.
