# Planning brief

## Context

A content-heavy WordPress publishing site needs a redesign to improve editorial workflow efficiency, content discoverability, and implementation readiness for a later PRD and estimate.

## Goals

- clarify the immediate planning scope
- identify the key evidence still needed before PRD drafting
- define the likely workstreams for design, content, and implementation planning

## Scope

- current-state planning review
- editorial workflow needs discovery
- information architecture implications
- technical planning constraints surfaced from the existing repo and source materials

## Non-scope

- final UI design decisions
- implementation task breakdown
- delivery estimate
- launch planning

## Constraints and dependencies

- current repo patterns may constrain the redesign path
- editorial stakeholders have not yet confirmed workflow priorities
- analytics and accessibility baselines are still missing
- source-of-truth design direction has not been validated

## Known risks

- the project may over-index on visual redesign without enough workflow evidence
- missing baseline evidence may lead to weak requirement prioritisation
- existing technical constraints may be discovered too late if repo review is delayed

## Open questions

- which editorial tasks are currently most painful?
- what publishing workflow outcomes define success?
- what accessibility and analytics issues already exist?
- does the current theme architecture need incremental improvement or replacement?

## Recommended next step

Run a source-backed PRD preparation pass only after confirming editorial workflow needs, baseline evidence, and the technical constraints from the current implementation.
