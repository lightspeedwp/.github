## Quick selection guide

| Prompt | Use it when you want to… | Reattach skills? | Update docs/specs? | Scope |
| :---- | :---- | ----: | ----: | :---- |
| **Phase 4** | verify parity between expected skills, attached skills, and workspace-shared skills | No | Light doc/report update allowed | Standard audit |
| **Phase 4B** | verify parity and **reattach exact shared matches** that are missing | Yes | Yes, minimal rebuild-doc update | Audit + repair |
| **Phase 4C** | verify parity, reattach exact matches, and **repair documentation/spec drift** | Yes | Yes, full doc/spec parity repair | Audit + repair + documentation hardening |
| **Phase 4D** | recover missing skills from the **workspace-shared directory only** | Yes | No | Recovery-only |
| **Phase 4E** | check the **workspace-shared directory only** with **no repair at all** | No | No | Narrow audit-only |

## What each version is for

### Phase 4

Use this when you want a **balanced verification pass**.

Best for:

- “Are the expected skills attached?”
- “Do the attached skills match the shared-skill set?”
- “What is missing or mismatched?”

Choose this when:

- you want a **proper parity audit**
- you do **not** want automatic reattachment yet
- you want a clean verification report first

Good default if you are unsure.

### Phase 4B

Use this when you want **verification plus automatic reattachment of exact shared matches**.

Best for:

- “If a shared skill exists and is missing, attach it.”
- “Repair obvious missing-skill gaps, but don’t invent replacements.”

Choose this when:

- you already know the expected skill list
- you want the builder to fix only **exact-match missing attachments**
- you want a new parity report after repair

Use this when you want **safe repair**, not just reporting.

### Phase 4C

Use this when you want the **most complete parity pass**.

Best for:

- “Make sure the actual attached skills, shared skills, inventory docs, routing docs, and per-skill specs all agree.”
- “Repair attachment parity and documentation parity together.”

Choose this when:

- the rebuild pack may be stale
- skill names or purposes may have drifted
- routing docs or skill specs may no longer match reality
- you want a **full audit trail**

This is the **strongest** version.

### Phase 4D

Use this when you want **workspace-shared skill recovery only**.

Best for:

- “Only check the shared directory and reattach exact matches.”
- “Do not touch docs, rollout files, or references.”

Choose this when:

- the rebuild docs are fine
- the problem is specifically **missing attachments**
- you want the narrowest safe repair pass

This is the best **repair-only** option.

### Phase 4E

Use this when you want the **narrowest possible audit**.

Best for:

- “Do the expected skills even exist in the shared directory?”
- “I want a shared-directory audit only.”
- “No reattachment, no docs, no side effects.”

Choose this when:

- you are still investigating
- you want zero repair actions
- you want to confirm whether the shared-skill layer itself is complete

This is the best **pre-repair diagnostic** option.

## Decision tree

### Use Phase 4E if

- you only want to inspect the workspace-shared directory
- you do not want any mutation
- you want the safest first diagnostic

### Use Phase 4D if

- you only care about recovering missing skills from the shared directory
- you do not want documentation touched

### Use Phase 4 if

- you want a standard parity audit across expected vs attached vs shared
- you want reporting first before any repair

### Use Phase 4B if

- you want a standard parity audit
- and you want exact-match missing skills reattached automatically

### Use Phase 4C if

- you want full parity verification
- and you also want rebuild files, routing docs, and skill specs brought back into alignment

## Recommended order in practice

If you want to be methodical:

1. **Phase 4E** — confirm what exists in the shared directory
2. **Phase 4** — compare expected vs attached vs shared
3. **Phase 4B** or **4D** — repair missing exact matches
4. **Phase 4C** — only if the documentation layer also needs hardening

If you want the fastest practical path:

- use **Phase 4B** for **audit + safe repair**
- use **Phase 4C** for **audit + safe repair + documentation parity**

## Recommendation for this agent

Given the goal of **rebuilding under another user and preserving skill parity precisely**, the best choices are:

- **Phase 4E** first if you want a clean, no-risk diagnostic
- **Phase 4B** if you want the most practical next step
- **Phase 4C** if you also want the rebuild pack to stay perfectly aligned with the real skill set

So the simplest recommendation is:

- **Use 4B for recovery**
- **Use 4C for full hardening**

## One-line summaries

- **4** = audit parity
- **4B** = audit parity + reattach exact matches
- **4C** = audit parity + reattach exact matches + fix docs/specs
- **4D** = shared-skill recovery only
- **4E** = shared-directory audit only
