## Purpose

Record the current validation outcome for the agent’s skills-routing and skills-directory layer after the recent LightSpeed attachment and routing updates.

## Validation result

The current scaffold is **partially aligned**.

The **agent instructions** and `references/skill-routing-spec.md` are aligned with the real attached skill layer, but the **prompt-library index** and **main skill inventory** are still stale. The **parity audit note** now overclaims that those repairs already happened.

## Blocking findings

None.

## Important findings

### 1. `references/SKILL_INVENTORY.md` still describes the wrong attached layer

- **Where:** `references/SKILL_INVENTORY.md`
- **Mismatch:** The file still describes an older exact-name shared-skill layer such as `lightspeed-project-intake-router`, `lightspeed-prd-generator`, `lightspeed-project-researcher`, and similar historical parity targets as if they are the current attached skills.
- **Why it matters:** This is the main skills-directory document. It now conflicts with the actual attached uploaded Builder skill layer and can mislead rebuild, handoff, promotion, and future routing repair work.
- **Smallest safe repair:** Rewrite the inventory so it distinguishes:
  - the attached LightSpeed lifecycle suite
  - the still-attached legacy helper layer
  - local draft-only skills that are not attached
  - the preserved historical exact-name parity track

### 2. `prompts/README.md` is still missing the newer skills-routing and directory prompts

- **Where:** `prompts/README.md`
- **Mismatch:** The index still lists only the older cleanup and audit prompt subset and omits the newer skills-routing and directory validation/repair prompts plus the newer scaffold-maintenance prompts already present in `prompts/`.
- **Why it matters:** The prompt-library index is now incomplete and weakens discoverability for future validation and repair passes.
- **Smallest safe repair:** Refresh the prompt inventory so it includes the full current prompt set, especially the skills-routing and directory validation/repair prompts.

### 3. `references/skill-parity-audit.md` now overclaims that the inventory and prompt index are already repaired

- **Where:** `references/skill-parity-audit.md`
- **Mismatch:** The parity note says the inventory and prompt index now reflect the repaired state, but `references/SKILL_INVENTORY.md` and `prompts/README.md` still show the older content.
- **Why it matters:** This creates second-order audit drift: one repair note claims the scaffold is fixed while the source files it references are still stale.
- **Smallest safe repair:** After fixing the inventory and prompt index, update the parity note so its “what is repaired now” section matches the actual repaired files.

## Cleanup-only findings

### 4. Local draft-only design skills are not represented clearly in the current directory layer

- **Where:** directory-level documentation overall
- **Mismatch:** `design-context-synthesis` and `design-qa-readiness` exist locally but are not attached. The current directory docs do not consistently separate draft-only support skills from attached routing skills.
- **Why it matters:** This is not a blocker for the current routing layer, but it can confuse future promotion and validation passes.
- **Smallest safe repair:** In the repaired skill inventory, add an explicit local-draft-only section for unattached support skills.
