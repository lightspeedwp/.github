## Purpose

Use this checklist to resolve the four remaining exact-name skill-parity gaps that could not be repaired automatically.

## Remaining unresolved skills

- lightspeed-figma-wordpress-technical-brief
- evidence-locker
- lightspeed-intake-onboarding
- lightspeed-launch-task-router

## Resolution standard

A gap is resolved only when one of these is true:

1. the exact expected skill name is verified and available in the workspace-shared directory, then attached
2. the workspace formally confirms the expected name has been retired and the parity target is updated deliberately
3. the rebuild standard is explicitly changed to accept a different verified source scope

Near matches do not resolve parity by themselves.

---

## 1. lightspeed-figma-wordpress-technical-brief

### What to check

- Whether the exact skill name exists in the workspace-shared skill directory
- Whether the skill exists under another shared scope
- Whether the skill was renamed to a different exact canonical name
- Whether the role is currently being covered only by a local uploaded Builder skill

### Where to check

- Workspace-shared skill directory
- Other shared-skill scopes visible to the owner or workspace admins
- Existing team documentation, release notes, or skill registry docs
- Any internal record of renamed or retired LightSpeed skills

### How to record the outcome

Record one of:

- `resolved: exact workspace-shared skill found and attached`
- `resolved: exact skill found under alternate shared scope; workspace decision required`
- `resolved: expected name retired; parity target updated to <new exact name>`
- `unresolved: no exact skill found`

Also record:

- who checked
- date checked
- source scope checked
- resulting action taken

---

## 2. evidence-locker

### What to check

- Whether the exact name `evidence-locker` exists in workspace-shared skills
- Whether `evidence-locking` is only a near-match local substitute rather than the expected shared source
- Whether the expected exact shared skill was renamed or retired

### Where to check

- Workspace-shared skill directory
- Other shared scopes
- Internal skill inventory or change log
- Team owners responsible for evidence-discipline skills

### How to record the outcome

Record one of:

- `resolved: exact workspace-shared skill found and attached`
- `resolved: expected name retired; parity target updated to <new exact name>`
- `unresolved: only near matches found`
- `unresolved: no exact skill found`

Also record:

- whether near-match variants were seen
- why those variants were not accepted automatically

---

## 3. lightspeed-intake-onboarding

### What to check

- Whether the exact name exists in workspace-shared skills
- Whether onboarding was renamed to another exact canonical LightSpeed onboarding skill
- Whether current onboarding variants are only near matches

### Where to check

- Workspace-shared skill directory
- Other shared scopes
- Internal onboarding or team-skill registry docs
- Team owners responsible for intake or onboarding workflows

### How to record the outcome

Record one of:

- `resolved: exact workspace-shared skill found and attached`
- `resolved: expected name retired; parity target updated to <new exact name>`
- `unresolved: only alternate onboarding variants found`
- `unresolved: no exact skill found`

Also record:

- which alternate onboarding variants were reviewed
- why they were not treated as equivalent automatically

---

## 4. lightspeed-launch-task-router

### What to check

- Whether the exact name exists in workspace-shared skills
- Whether the exact name exists only in broader shared scope
- Whether the rebuild standard accepts broader shared scope for this one skill
- Whether the workspace can promote or expose this skill into workspace-shared scope

### Where to check

- Workspace-shared skill directory
- Broader shared-skill scope
- Workspace admin or skill owner controls
- Internal rebuild policy for accepted shared scopes

### How to record the outcome

Record one of:

- `resolved: exact workspace-shared skill found and attached`
- `resolved: broader shared scope explicitly accepted for rebuild parity`
- `resolved: promoted into workspace-shared and attached`
- `unresolved: exact skill exists only outside workspace-shared and no policy exception approved`

Also record:

- whether a scope exception was approved
- who approved it
- whether the rebuild docs were updated to reflect that policy
