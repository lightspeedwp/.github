# templates/

## Purpose
Store the canonical planning-output templates that the agent should use for consistent structure, section order, and terminology.

## Current files in this folder
- `project-intake-summary-template.md` — canonical intake summary structure for rough or mixed planning inputs.
- `planning-brief-template.md` — structure for a pre-PRD planning brief.
- `prd-template.md` — evidence-led PRD structure for implementation and estimation readiness.
- `technical-brief-template.md` — technical mapping structure for validated planning work.
- `gap-analysis-template.md` — structure for identifying missing evidence and the safest next step.
- `estimate-pack-template.md` — estimate output structure for estimate-ready planning packs only.
- `handoff-pack-template.md` — delivery-ready handoff structure.
- `quality-review-template.md` — artefact-review structure for quality and readiness checks.
- `project-status-update-template.md` — concise project-status structure.
- `validation-report-template.md` — validation output structure for file, scaffold, or workflow checks.

## Naming conventions
- Use lowercase kebab-case.
- End template files with `-template.md`.
- Match the template name to the output type it governs.
- Keep templates canonical and minimally filled; worked examples belong in `examples/templates/`.

## Important distinction
Templates define the standard blank or scaffold output shape. Filled examples that demonstrate what good outputs look like belong in `examples/templates/`, not here.
