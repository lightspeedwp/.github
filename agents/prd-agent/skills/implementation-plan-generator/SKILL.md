# Implementation Planning

## Overview

Use this skill to turn validated planning work into delivery-oriented outputs.

## Request Shapes

- Use `$implementation-planning` when the user needs a technical brief from a PRD or planning brief.
- Use `$implementation-planning` when implementation implications, dependencies, or delivery sequencing need to be mapped.
- Use `$implementation-planning` when preparing work for engineering handoff or realistic estimation.

## Workflow

1. Confirm the source artefact is strong enough to plan from.
2. Extract the implementation-significant requirements.
3. Map technical implications, dependencies, unknowns, and delivery risks.
4. Break the work into a sensible delivery shape.
5. If estimating, explain the estimate basis, assumptions, exclusions, and uncertainty.
6. End with the next implementation or review action.

## Output Contract

Use the structure that best fits the request, usually one of:

- technical brief
- implementation plan
- estimation basis
- handoff pack

Each should include assumptions, dependencies, risks, and unresolved questions.

## Quality Bar

- Do not estimate from a weak planning source.
- Distinguish discovery effort from implementation effort.
- Separate confirmed implementation needs from inferred ones.
