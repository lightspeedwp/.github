# Team Onboarding Guide

---

## What this agent is for

This agent is a focused **Linear-first advisor**.

Use it to:

- improve how LightSpeed uses Linear;
- audit Linear workflows and intake patterns;
- rewrite rough issues into clearer Linear-ready work;
- recommend better triage, routing, and prioritization decisions; and
- suggest durable Memory updates that improve future Linear-focused runs.

Do not use it as a general agency assistant by default.

---

## Who should use it

This rollout is best for teammates who:

- shape or review work in Linear;
- triage or route incoming work;
- prepare planning or handoff assets; or
- want faster, clearer recommendations for recurring Linear work.

---

## What good usage looks like

Good first requests are:

- “Audit this Linear workflow and show the biggest gaps.”
- “Rewrite this rough issue into a clearer Linear-ready task.”
- “Recommend the best triage route and owner direction for this.”
- “Review this project and tell me the clearest next focus.”
- “Tell me what should be saved to Memory from this recurring workflow.”

The best requests are concrete, scoped, and tied to a real workflow.

---

## Before a teammate starts

Each tester should:

- understand the agent is **Linear-first**;
- know which workflow, project, or issue set they want to test;
- bring a real brief, issue set, SOP, or workflow example when possible; and
- avoid requesting live writes unless they explicitly want that and are ready to approve them.

---

## Recommended first-use flow

1. Start with one real Linear-related task.
2. Ask for a read-first output before asking for edits or writes.
3. Review whether the output is specific, reusable, and aligned with LightSpeed conventions.
4. Note any places where the agent is too broad, too vague, or too generic.
5. Capture useful feedback in the rollout scorecard or pilot notes.

---

## Expected behaviours

Testers should expect the agent to:

- stay focused on Linear-centered work;
- prefer read-first recommendations;
- separate evidence from assumptions;
- produce structured, copy-ready outputs; and
- use attached specialist skills only when they materially improve the result.

---

## What to watch for

Flag it if the agent:

- becomes a broad general operations assistant;
- overuses non-Linear apps when Linear should lead;
- makes unsupported assumptions;
- proposes writes too aggressively;
- produces generic workflow advice instead of a practical Linear output; or
- stores temporary details as if they were durable memory.

---

## Feedback prompts for testers

Ask testers to comment on:

- clarity of outputs;
- usefulness for real Linear work;
- accuracy of routing and workflow recommendations;
- whether the agent feels focused enough;
- whether onboarding and starter prompts make sense; and
- where direct answers were strong versus where specialist skills helped.

---

## Pilot success signal

The pilot is working if teammates can use the agent to get faster, clearer, more reusable Linear workflow outputs with minimal confusion and without the agent drifting out of scope.
