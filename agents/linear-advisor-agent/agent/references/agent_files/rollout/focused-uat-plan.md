# Focused UAT Plan

---

## Goal

Run a small, high-signal user acceptance test for the **LightSpeed Linear Advisor**.

The purpose of this UAT pass is to validate:

- usefulness for real Linear-centered work;
- correctness of Linear-first recommendations;
- quality of issue shaping, triage, and routing guidance;
- quality of durable Memory judgment and reuse; and
- clarity of the rollout assets and handoff materials.

---

## Pilot Scope

Use a focused pilot with 3 to 5 internal testers.

Prioritize realistic LightSpeed Linear work such as:

- Linear workflow audits;
- issue rewrite and issue-shaping requests;
- triage and routing recommendations;
- stalled-work and momentum review;
- duplicate-handling recommendations;
- project health and prioritization reviews; and
- narrow durable-default or Memory recommendations based on recurring workflow patterns.

Keep the pilot read-first by default.

Do not use this pilot to test a broad general agency-workflow role.

## Tester Tasks

Each tester should complete a small set of realistic Linear-focused tasks.

Recommended task mix:

1. run one Linear workflow-audit request;
2. run one issue-shaping or issue-rewrite request;
3. run one triage, routing, or duplicate-handling request;
4. run one project-momentum or project-health review; and
5. log findings in the scorecard or team feedback tracker.

Optional fifth task:

- ask for one narrow durable-default or Memory recommendation based on recurring Linear workflow patterns.

---

## Evaluation Criteria

Score each run using the checklist and scorecard materials in this folder.

Primary criteria:

- relevance to real LightSpeed Linear work;
- correctness of triage, routing, and issue-shaping recommendations;
- factual grounding and evidence discipline;
- clarity and usefulness of the output;
- scope discipline, especially staying Linear-first;
- quality of durable Memory judgment; and
- overall confidence to use the output in real workflow review or planning.

---

## Pass / Watch / Fix Thresholds

**Pass**

- outputs are consistently useful and copy-ready;
- recommendations stay Linear-first and do not drift broad;
- no major evidence or permission mistakes appear; and
- testers would use the agent again for similar Linear work.

**Watch**

- outputs are mostly good but need wording, formatting, or routing refinement; or
- some recommendations are too generic, too broad, or not specific enough to the current Linear workspace.

**Fix**

- outputs misuse tools or permissions;
- outputs drift into a broad workflow-agent role;
- issue shaping, triage, or routing advice is weak or unreliable; or
- testers cannot rely on the outputs without heavy rewriting.

---

## Pilot Review Process

At the end of the pilot:

1. review tester notes and scorecards;
2. summarize repeated strengths and repeated failures;
3. identify the top instruction, starter-prompt, file, or guardrail fixes;
4. decide which fixes are required before a wider Linear-team rollout; and
5. produce a short next-version recommendation.

---

## Success Criteria

The focused UAT pass is successful when:

- testers can complete the planned Linear scenarios with the rollout kit;
- the agent behaves like a narrow Linear-first advisor;
- app and approval guidance stays accurate and conservative;
- the rollout package is clear enough for handoff; and
- the team has a short, prioritized fix list for the next revision.
