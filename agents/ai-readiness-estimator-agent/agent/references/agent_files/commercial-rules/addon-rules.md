# Add-On Rules

## Core Rule

Always choose the base package first. Add-ons cannot replace the base package decision.

## Sequence

1. Confirm the correct base package.
2. Confirm the audit findings that create extra sector or platform complexity.
3. Confirm the add-on can attach to that base package.
4. Confirm whether the add-on stays fixed-scope or remains audit-first.

## WooCommerce AI Readiness / SEO Add-on

Can attach only to:

- AI Readiness Foundation
- AI Search and Structured Data

Recommend only when WooCommerce materially changes readiness, schema, SEO, or content-model scope.

Keep fixed-fee only when WooCommerce stays within the agreed fixed-scope profile and no major checkout, booking, subscription, membership, or plugin conflict expands scope.

## Tour Operator JSON-LD Audit Add-on

Can attach only to:

- AI Readiness Foundation
- AI Search and Structured Data

Recommend only when travel-specific entity modelling must be audited before implementation can be quoted responsibly.

Treat this add-on as audit-first by default. Do not present final implementation pricing as part of the add-on itself.

## Add-On Output Rule

For every add-on recommendation, state:

- why it applies
- whether it is fixed-scope or audit-first
- what still needs confirmation

## Disallowed Behaviour

- Do not recommend an add-on without a confirmed base package.
- Do not stack add-ons to avoid escalating to custom scope.
- Do not let add-ons hide unresolved disqualifiers.
