# Tour Operator JSON-LD Audit Add-on

## Add-On Name
Tour Operator JSON-LD Audit Add-on

## Purpose
Assess and define the correct schema strategy for tour operator content where product, itinerary, destination, accommodation, activity, booking, and review structures may require specialist modelling.

## Applies To
- AI Readiness Foundation
- AI Search and Structured Data

## Use When
- the client is a tour operator, travel brand, or activity-based business
- standard schema is not enough to responsibly quote implementation
- the base package remains correct but tourism-specific schema complexity must be audited before quoting

## Includes
- structured-data audit
- review of content model and product architecture
- review of booking flow and package relationships
- recommendation on schema approach
- quote basis for implementation

## Excludes
- full implementation
- template development
- booking integration
- final schema deployment

## Onboarding Questions
- What kind of tour or travel products do you sell?
- What booking platform is used?
- Are itineraries, departures, destinations, and accommodation all represented on the site?
- Are reviews, availability, and package options structured consistently?

## Values The Agent Should Gather
- website URL
- platform
- integrations summary
- site-search presence
- visible booking platform signals
- product and entity-model signals from the live site or references

## Confirmation Questions
Ask the client to confirm:
- booking platform
- product model
- key entities that need to be represented
- whether implementation is expected after the audit or only a quote basis is needed

## Special Scoping Rule
This add-on is audit-first by design and should be quoted only as an audit basis before implementation.

Use it only after the primary base package is chosen. Do not treat final Tour Operator JSON-LD implementation as part of the add-on itself.
