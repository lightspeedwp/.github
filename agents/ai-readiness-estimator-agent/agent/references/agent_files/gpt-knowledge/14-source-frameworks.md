Use these frameworks as reference points when creating AI readiness, governance, content and chatbot outputs.

Do not overload client-facing documents with standards unless they support a practical recommendation.

## NIST AI Risk Management Framework

Use for risk-based thinking, governance, mapping, measurement and management of AI risks.

## ISO/IEC 42001

Use for AI management-system thinking: ownership, repeatable processes, documented review cycles and continuous improvement.

## EU AI Act

Use for risk-based AI system thinking and transparency expectations, especially where users interact directly with AI systems.

## UK ICO AI and data protection guidance

Use for data protection, lawful processing, fairness, transparency, security and personal data considerations.

## POPIA

Use where South African privacy principles are relevant, including personal information, processing limitations, purpose, security safeguards and accountability.

## OWASP Top 10 for LLM Applications

Use for practical AI and chatbot risk controls, especially:

- prompt injection
- sensitive information disclosure
- insecure output handling
- excessive agency
- vector and embedding weaknesses
- supply chain and integration risks

## WCAG 2.2 and W3C evaluation guidance

Use for accessibility requirements in websites and chatbot experiences.

Relevant areas:

- keyboard access
- focus management
- labels
- headings
- contrast
- readable error messages
- accessible forms
- chatbot transcript readability

## Google Search Central

Use for:

- useful content
- responsible use of generative AI-assisted content
- structured data
- Core Web Vitals
- search visibility
- crawl/index issues

## WordPress best practice

Use for:

- maintainability
- block themes
- patterns
- `theme.json`
- plugin governance
- security and updates
- performance
- editorial workflows
- reusable content structures

## LightSpeed interpretation

For LightSpeed work, these frameworks should translate into practical outputs:

- source-of-truth registers
- approval workflows
- content ownership
- chatbot source boundaries
- escalation rules
- launch gates
- performance/accessibility checks
- governance review cycles
- maintainable WordPress architecture
