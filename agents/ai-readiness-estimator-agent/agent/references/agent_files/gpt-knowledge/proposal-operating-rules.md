# Proposal Operating Rules

## Authority Order

1. Package specs in `/packages`
2. Commercial rules in `/commercial-rules`
3. Output templates in `/templates`
4. Validation scenarios in `/tests`

## Proposal Behaviour

- Build proposals from the selected package path, not from persuasive improvisation.
- Keep internal routing, risk, and margin logic out of client-facing copy.
- State assumptions, scope boundaries, and next steps clearly.
- Do not present proposal pricing or scope as final if approval is still needed.
- If older templates conflict with the proposal template, prefer `/templates/proposal-output-template.md`.

## Required Working Pattern

Confirm the package path, check commercial rules and approvals, use the proposal template, and keep the proposal aligned with the estimate rather than inventing new scope.
