## Purpose

This file is the durable routing map for the estimator agent’s AI package system.

Use it to:

- select the correct primary AI base package
- explain why that package fits
- decide whether a project remains fixed-fee eligible
- identify when add-ons should be considered after the base package path is chosen

## Operating Rules

- Base package first, add-ons second.
- Every package starts with an audit of the live website and available references.
- Gather information in batches:
  1. reference sources
  2. live website or platform discovery
  3. business goals and package intent
  4. scope confirmation and commercial routing
- For every field, try to source it automatically first, show what was found, then ask the client to confirm or correct it.
- Ask only for missing values.
- If Gmail, Figma, GitHub, or another source is not connected, do not imply that it was scanned.

## Base Packages

### 1. AI Readiness Foundation

Use when:

- the site needs baseline AI, SEO, measurement, and content-readiness work
- no prior AI readiness work appears to exist
- the client needs a first implementation package rather than only strategy

### 2. AI Search and Structured Data

Use when:

- the client already has a reasonable baseline
- the next need is schema, crawl logic, machine readability, and validation

### 3. AI Chatbot Planning Workshop

Use when:

- the client wants a chatbot but use case, boundaries, content sources, or escalation rules are not yet defined

### 4. AI Chatbot with AI Engine — Starter

Use when:

- the client needs a simple FAQ, service, or enquiry-routing assistant
- no advanced integrations or guided qualification flows are required

### 5. AI Chatbot with AI Engine — Tailored

Use when:

- the client needs structured lead qualification, product-aware routing, or richer business-specific conversation paths

### 6. Yoast AI Content Training

Use when:

- the client team manages content internally and needs enablement after or alongside implementation

### 7. Ongoing AI Governance and Optimisation Retainer

Use when:

- AI readiness or chatbot work is already live and requires recurring review, tuning, and governance support

## Routing Logic From Audit Findings To Package Recommendation

### Step 1: Confirm the audit-first position

Every package begins with an audit of the live website and available references to identify irregularities, technical debt, content gaps, and disqualifiers.

### Step 2: Choose the primary base package

- Route to **AI Readiness Foundation** when the site needs a first baseline implementation path.
- Route to **AI Search and Structured Data** when baseline readiness exists and the next need is machine readability, crawl logic, or schema validation.
- Route to **AI Chatbot Planning Workshop** when chatbot intent exists but the use case, sources, rules, or scope are still undefined.
- Route to **AI Chatbot with AI Engine — Starter** when the chatbot brief is clear and the required behaviour stays within a simple bounded FAQ or service-routing model.
- Route to **AI Chatbot with AI Engine — Tailored** when the chatbot brief is clear but the required behaviour includes richer business logic, qualification, or routing.
- Route to **Yoast AI Content Training** when the main need is internal enablement after or alongside implementation.
- Route to **Ongoing AI Governance and Optimisation Retainer** when delivery is already live and the next need is recurring review and tuning.

### Step 3: Check fixed-fee eligibility

All packages are fixed-fee unless the audit identifies conditions that push the project beyond standard scope.

### Step 4: Escalate to custom-scope handling when the audit reveals

- severe technical instability
- major plugin conflicts
- substantial content contradictions
- complex regulated or sensitive AI use cases
- complex integrations not covered by package scope

## Add-On Rule

Consider add-ons only after the primary base package is chosen.

Current AI add-ons:

- WooCommerce AI Readiness / SEO Add-on
- Tour Operator JSON-LD Audit Add-on

Do not recommend an add-on as the primary path. Use it only when the base package remains correct and the audit shows that sector-specific scope must be layered on afterward.
