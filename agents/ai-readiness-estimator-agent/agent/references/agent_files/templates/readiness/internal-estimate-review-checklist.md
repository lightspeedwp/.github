# Internal Estimate Review Checklist

Use this checklist before an internal AI-readiness estimate is reused, approved, adapted for a client, or used to support package or scope decisions.

## Recommendation Quality

- [ ] The base package is chosen before any add-ons are discussed.
- [ ] The recommendation explains why the chosen package fits better than the alternatives.
- [ ] The recommendation defaults to **AI Readiness Foundation** only when the evidence supports a baseline-readiness route.
- [ ] The recommendation does not force a standard package when custom-scope handling is clearly more appropriate.

---

## Evidence Quality

- [ ] Verified facts are clearly separated from assumptions.
- [ ] Missing values are clearly listed.
- [ ] Risks and open questions are explicit.
- [ ] No unsupported claims or invented details appear.
- [ ] The estimate does not overstate access, approvals, rollout status, or hidden configuration.

---

## Commercial Safety

- [ ] Fixed-fee confidence is stated honestly.
- [ ] Scope certainty is not overstated.
- [ ] Exclusions are clearly defined.
- [ ] Add-ons are only discussed after the base package is justified.
- [ ] Approval-dependent or provisional language is used where appropriate.

---

## Output Structure

- [ ] The document uses the required section order.
- [ ] The title, intro, and summary table are present where expected.
- [ ] Divider lines and heading hierarchy are consistent.
- [ ] The output is easy to scan and practically useful.
- [ ] Next steps are concrete and actionable.

---

## Markdown And Link Safety

- [ ] No local workspace path appears.
- [ ] No sandbox path or temporary file location appears.
- [ ] No fake download link or unusable URL appears.
- [ ] Markdown-source output follows the required fenced or fallback rules.
- [ ] The final visible output stays compliant if renderer-added attributes are present.

---

## Final Review Decision

- [ ] Ready for internal reuse
- [ ] Ready with caveats
- [ ] Needs revision before reuse
