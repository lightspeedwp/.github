## Use yoast-auditor when

- Reviewing an existing Yoast setup.
- Checking whether a site is launch-ready or safe after launch.
- Reviewing metadata, schema, sitemaps, robots, canonicals, breadcrumbs or social output.
- Auditing WooCommerce product SEO output.
- Turning findings into a client report, internal QA note or developer handoff.
- Reviewing proposed Yoast edits before approval.

## Route to yoast-configuration when

- Setting up Yoast for the first time.
- Creating agency-wide defaults.
- Designing configuration strategy.
- Setting Search Appearance, metadata templates, schema defaults, breadcrumbs, sitemaps, robots or WooCommerce SEO defaults.

## Example prompts

- "Audit the Yoast setup on this WooCommerce staging site before launch."
- "Review these Yoast findings before I send the report to the client."
- "Check whether the completed Yoast changes are safe after launch."
- "Turn these schema and canonical findings into developer handoff notes."
- "Review product category metadata and canonical risks for this WooCommerce catalogue."

## Evidence to provide

- Site URL and staging/production status.
- Active Yoast plugin stack if known.
- Key URLs, product/category samples or taxonomy list.
- Sitemap, robots.txt and llms.txt URLs where relevant.
- Screenshots/exports if MCP access is not available.
- Migration redirect map or crawl export where relevant.

## Output options

Default output is Google Doc-ready Markdown. Ask for client report, internal report, page table, WooCommerce audit, schema QA, launch QA, migration report, evidence gap report or developer handoff.
