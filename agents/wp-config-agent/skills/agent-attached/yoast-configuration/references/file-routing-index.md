Use this index when maintaining the Yoast configuration skill or when a task could load several supporting files. The goal is to keep `SKILL.md` small while making file selection predictable.

## Routing principles

- Load the fewest files that can answer the current request safely.
- Load intake files before making recommendations when missing site context would change the answer.
- Load reference files before templates when the answer depends on Yoast behaviour or product scope.
- Load templates only when producing a reusable deliverable.
- Load schemas, fixtures, scripts and tests only for structured validation, package QA or automation.
- Treat source-register rows marked `research target` as scan targets, not verified evidence.

## Collision handling

When a request matches multiple routes:

1. Prefer the route that matches the site type first.
2. Add the feature reference only when behaviour or output needs explaining.
3. Add the developer reference only when code, filters, APIs, theme integration, custom plugins or plugin conflicts are involved.
4. Add the source register when the answer needs evidence traceability or current verification.
5. Add templates only after the recommendation or audit structure is clear.

## Maintenance notes

- Update this index whenever a new reference, intake, profile, template, script or test file is added.
- Keep settings-export review, rendered-output QA, audit triage, troubleshooting, decision logging, conflict handling and source freshness routes separate so normal configuration answers do not become unnecessary research packs.
- Keep file paths exact so `scripts/validate_skill_structure.py` can check references reliably.
- Do not duplicate deep reference content here; this file is a routing map only.

## Comparison and regression routing notes

- For settings-only comparisons, load `references/settings-export-review-playbook.md` and mark live-output checks as required.
- For rendered-output comparisons, load `references/rendered-output-qa-playbook.md` and classify differences using `references/state-comparison-playbook.md`.
- For plugin-update checks, load `references/plugin-update-regression-playbook.md` before writing a release recommendation.
- For acceptance gates, use `templates/yoast-acceptance-criteria.md` and keep each criterion evidence-led and pass/fail.
- If a risky regression is accepted, route to `references/decision-register-model.md` and `templates/yoast-decision-log.md`.
