Use this when a Yoast recommendation depends on WordPress content structure, templates, archives, taxonomies, or plugin interactions.

## Structure questions

1. Which public post types exist? Include posts, pages, products, events, resources, case studies, team, testimonials, locations, tours, accommodation, or custom types.
2. Which taxonomies exist? Include categories, tags, product categories, product tags, attributes, locations, topics, sectors, formats, authors, or custom taxonomies.
3. Which archives should be useful landing pages and which are thin utility views?
4. Are author archives, date archives, internal search pages, media attachment URLs, and paginated archives currently indexable?
5. Are any templates generated by the block theme, custom plugin, page builder, WooCommerce, multilingual plugin, or custom routing?
6. Which plugins may output metadata, schema, Open Graph, breadcrumbs, redirects, sitemaps, robots rules, or canonical tags?
7. Are there existing custom fields used for titles, descriptions, product data, schema, social images, or content relationships?

## Evidence to request

- Content-type list and taxonomy list.
- Yoast settings export or screenshots.
- Sitemap index and representative sitemap URLs.
- Rendered source for homepage, page, post, archive, taxonomy, author archive, and any custom post type.
- Crawl export showing titles, descriptions, canonicals, status codes, meta robots, and sitemap inclusion.

## Safe defaults

- Index only content types and taxonomies that have unique content value.
- Noindex thin or internal utility archives unless they are deliberately curated landing pages.
- Redirect or disable attachment URLs where they create duplicate thin pages.
- Align noindex decisions with sitemap exclusion.
- QA rendered output rather than relying only on settings screens.
