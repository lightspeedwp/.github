# Memory Layer Consistency Prompt

Review the current `memory/` layer, its documentation, and any surrounding maintenance references so durable working-memory guidance stays aligned with the current attached files and validation rules.

Scope and intent:

- This is a memory-layer consistency task, not a redesign of the agent’s Memory strategy.
- Treat the current `memory/` files, current instructions, current validation docs, and current schemas as the source of truth.
- Focus on folder purpose, file roles, maintenance rules, and consistency with the rest of the file structure.

Primary goal:

- Keep the memory layer documented accurately and maintainable without drifting into templates, examples, references, or scratch-space behaviour.

What to review:

1. `memory/README.md`
2. Current files in `memory/`
3. Root and validation docs that describe the memory layer
4. Related schemas and validators where they govern memory hygiene or structure

What to check for:

- stale memory inventories
- memory guidance that conflicts with the current file roles
- wording that blurs durable memory with reusable references or examples
- validation assumptions that no longer match the current memory files
- duplicated or contradictory memory maintenance notes across docs

Editing rules:

- Make the smallest complete set of edits needed.
- Preserve the current durable-memory model unless a real inconsistency requires clarification.
- Do not invent new memory folders or files unless the task clearly calls for them.

Output:

1. Memory-layer files and docs reviewed
2. Files updated
3. Any memory-hygiene or documentation gaps found
4. Any follow-up validation checks worth adding later
