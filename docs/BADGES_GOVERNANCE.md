# Badge Governance & Procedures

**Status:** Active  
**Version:** 1.0.0  
**Last Updated:** 2026-08-08  
**Owner:** Ash Shaw

---

## Overview

This document defines governance policies, naming conventions, and procedures for managing badges in the LightSpeed organisation. Badges provide visual status indicators for documentation, workflows, and project metadata.

---

## 1. Badge Types

### 1.1 Workflow Status Badges

**Purpose:** Display real-time status of GitHub Actions workflows

**Format:** GitHub's standard workflow badge (`badge.svg?branch=BRANCH`)

**Updated:** Automatically on workflow completion

**Examples:**

- ![Checks](https://img.shields.io/badge/Checks-passing-success.svg)
- ![Release](https://img.shields.io/badge/Release-passing-success.svg)

**Source:** `.github/workflows/*.yml` (discovered automatically)

**Configuration:** `.github/automation/badges.schema.yml`

---

### 1.2 Metadata Badges

**Purpose:** Display document metadata (license, status, file type)

**Format:** shields.io style badges (`img.shields.io/badge/...`)

**Updated:** On document change (frontmatter modification)

**Examples:**

- ![License MIT](https://img.shields.io/badge/license-MIT-blue.svg)
- ![Status Active](https://img.shields.io/badge/status-active-success.svg)
- ![Type Documentation](https://img.shields.io/badge/type-documentation-lightblue.svg)

**Source:** Document frontmatter (YAML front matter)

**Configuration:** `.github/automation/badges.schema.yml` mapping rules

---

### 1.3 Custom Badges

**Purpose:** Project-specific badges for custom workflows or metrics

**Format:** shields.io badges with custom parameters

**Updated:** As needed via workflow dispatch

**Examples:**

- ![Coverage 85%](https://img.shields.io/badge/coverage-85%25-success.svg)
- ![Phase Phase 3](https://img.shields.io/badge/phase-Phase%203-blue.svg)

**Source:** Manually created or generated by custom workflows

**Approval Required:** Yes (must be approved via code review)

---

## 2. Badge Naming Conventions

### 2.1 Workflow Badge Names

**Pattern:** `{workflow-name}` (kebab-case, no .yml extension)

**Examples:**

- `checks` (from `checks.yml`)
- `docs-validation` (from `docs-validation.yml`)
- `main-branch-guard` (from `main-branch-guard.yml`)

**Source of Truth:** `.github/workflows/*.yml` directory

---

### 2.2 Metadata Badge Names

**Pattern:** `{metadata-type}:{value}` or `{metadata-type}`

**Examples:**

- `license:MIT`
- `status:active`
- `type:documentation`
- `phase:Phase 3`

**Allowed Metadata:**

- `license` — Document license (MIT, GPL-3.0, Apache-2.0, CC-BY-4.0)
- `status` — Document status (active, archived, draft, deprecated)
- `type` — Document type (documentation, guide, specification, automation)
- `phase` — Project phase (Phase 1, Phase 2, etc.)
- `area` — Topic area (ci, docs, automation, security)

**Manual Placement:**

1. Add markers to your document after the main heading
2. Leave content between markers blank
3. Workflow will populate automatically
4. Do not modify content between markers (will be overwritten)

**Validation:**

- Markers must be on separate lines
- Must use exact comment format (no variations)
- Both markers required (start AND end)

## 4. Badge Coverage Rules

### 4.1 Which Documents Get Badges

**Rule:** Badges are applied based on document type and frontmatter

**Included Document Types:**

- `type: documentation` — User-facing documentation
- `type: specification` — Technical specifications
- `type: guide` — How-to and procedural guides
- `type: workflow` — Workflow documentation
- `type: automation` — Automation and CI/CD

**Excluded Document Types:**

- Temporary files (`.tmp`, `.bak`)
- Archive documents (`status: archived`)
- Internal-only documents (not in user-facing paths)
- Auto-generated files

### 4.2 Which Workflows Get Badges

**Critical Workflows (Always Included):**

- `checks` — Core validation
- `docs-validation` — Documentation integrity
- `gitleaks` — Secret scanning
- `main-branch-guard` — Main branch protection
- `labeling-governance` — Label enforcement
- `metadata-governance` — Metadata compliance
- `release` — Release coordination
- `template-enforcement` — Template compliance
- `validate-pr-template` — PR template validation

**Optional Workflows (Conditional):**

- Included if document tags match workflow category
- Examples: `labeling`, `issue-labeling-automation` for issue-related docs

**Excluded Workflows:**

- Deprecated or archived workflows
- Internal-only workflows
- Reusable workflows (not publicly visible)
- One-off or testing workflows

## 5. Update Procedures

### 5.1 Automatic Updates (On-Push Trigger)

**When:** Every push to `develop` branch with documentation changes

**What:** Documentation badges are regenerated and updated

**Behavior:**

- Scans changed `.md` files
- Detects marker comments
- Generates badges based on schema + frontmatter
- Updates files in-place
- Creates commit if changes made

**Trigger Workflow:** `.github/workflows/badges-documentation-update.yml`

---

### 5.2 Scheduled Updates (Daily)

**When:** Every day at 00:00 UTC

**What:** Status badges are validated and README updated

**Behavior:**

- Validates all badge URLs (HTTP check)
- Queries GitHub API for workflow status
- Updates README status badges
- Reports broken links (issue creation)
- Logs coverage metrics

**Trigger Workflow:** `.github/workflows/badges-readme-status.yml`

---

### 5.3 Workflow Discovery (Daily)

**When:** Every day at 01:00 UTC

**What:** Detects new/deleted workflows and updates schema

**Behavior:**

- Scans `.github/workflows/` directory
- Compares against schema
- Auto-adds new workflows
- Creates issue for deleted workflows
- Reports coverage percentage

**Trigger Workflow:** `.github/workflows/badges-workflow-audit.yml`

---

### 5.4 Manual Updates (Dispatch)

**When:** On demand via GitHub Actions manual dispatch

**What:** Regenerate all badges or specific document type

**Options:**

- Full regeneration (all documents)
- Document type specific (e.g., "docs only")
- Workflow specific (e.g., "update checks badge")

**Access:** Repository maintainers only

---

## 6. Broken Badge Reporting

### 6.1 Detection

**Automated Detection:** Weekly health check workflow

**Manual Detection:** Visual inspection of documentation

**What Triggers Issue Creation:**

- HTTP 404 errors (URL returns not found)
- Timeout errors (>10 second response)
- Redirect chains (>3 redirects)
- Workflow no longer exists

---

### 6.2 Response Procedures

**For Missing Workflows:**

1. Verify workflow was deleted intentionally
2. If deleted: Remove from schema
3. If moved/renamed: Update schema with new path
4. Close issue when resolved

**For Invalid URLs:**

1. Check schema for typos
2. Verify workflow file exists
3. Update schema if needed
4. Re-run validation workflow

**For Timeout Issues:**

1. Increase timeout threshold (if warranted)
2. Check GitHub API status
3. Retry validation manually
4. If persistent: Report to GitHub Support

## 7. Schema Management

### 7.1 Schema Location

**File:** `.github/automation/badges.schema.yml`

**Access:**

- Read: All team members
- Modify: Via pull request (code review required)

**Validation:** Automatic YAML schema validation on push

---

### 7.2 Schema Updates

**When to Update:**

- New workflow added to `.github/workflows/`
- Workflow removed or renamed
- New metadata badges needed
- Badge mapping rules need adjustment

**How to Update:**

1. Edit `.github/automation/badges.schema.yml`
2. Add/modify workflow definitions or mapping rules
3. Test locally: `npm run validate:schema`
4. Create PR with changes
5. Code review required
6. Merge to `develop`
7. Workflow discovery workflow auto-detects and syncs

---

### 7.3 Schema Versioning

**Format:** Semantic versioning (MAJOR.MINOR.PATCH)

**Version Location:** Schema file header and `versions` section

**Increment Rules:**

- **MAJOR:** Breaking changes to badge format or structure
- **MINOR:** New badges or workflows added
- **PATCH:** Bug fixes or documentation updates

---

## 8. Badge Lifecycle

### 8.1 Creation

**Process:**

1. Workflow added to `.github/workflows/`
2. Weekly discovery workflow detects new workflow
3. Schema auto-updated with new workflow definition
4. PR created for review
5. On merge, badges become available

**Timeline:** Within 7 days of workflow creation

---

### 8.2 Active Use

**Maintenance:**

- Status updated on every workflow run
- Weekly validation ensures links are valid
- Coverage metrics tracked
- Team can add/remove from specific documents

---

### 8.3 Deprecation

**Process:**

1. Workflow scheduled for removal (30-day notice)
2. Badge health check reports deprecation
3. Team removes badges from documents
4. Schema updated to mark as deprecated
5. On merge, badges stop generating
6. Workflow removed from `.github/workflows/`

---

### 8.4 Archive

**When:** Workflow no longer used but history preserved

**Storage:** Moved to `.github/workflows/archive/` or removed from schema

**Badges:** Removed from all documents

## 9. Decision Trees

### 9.1 "Should This Document Have Badges?"

```
Is the document user-facing?
├─ NO: Skip badges (internal docs, temp files)
└─ YES: Does it match a covered document type?
    ├─ NO: Skip badges (consider adding to coverage)
    └─ YES: Add markers and let workflow generate
```

---

### 9.2 "What Badge Type Should I Use?"

```
Do I need real-time status?
├─ YES (workflow running): Use workflow badges
└─ NO (static metadata): Use metadata badges

For metadata:
- License info? Use "license" badge
- Status (active/archived)? Use "status" badge
- Document type? Use "type" badge
- Custom metric? Use shields.io custom badge
```

---

### 9.3 "How Do I Update Badges?"

```
Is it a document change (text/structure)?
├─ YES: Push to develop, on-push workflow handles it
└─ NO: Is it a workflow addition/deletion?
    ├─ YES (new workflow): Weekly discovery handles it
    └─ NO: Is it a status validation needed?
        ├─ YES: Run scheduled workflow manually
        └─ NO: Check documentation/markers
```

## 10. Troubleshooting

### 10.1 Badges Not Appearing

**Checklist:**

- [ ] Document has correct markers (`<!-- BADGES-START -->` / `<!-- BADGES-END -->`)
- [ ] Document has frontmatter (`---` at start)
- [ ] Document type is in coverage list
- [ ] `.github/automation/badges.schema.yml` exists
- [ ] Workflow has completed successfully at least once
- [ ] Check workflow logs for errors

**Solution:**

```bash
# Run workflow manually
gh workflow run badges-documentation-update.yml -b develop

# Check logs
gh workflow view badges-documentation-update.yml --log
```

---

### 10.2 Broken Badge Links

**Checklist:**

- [ ] Workflow file still exists at expected path
- [ ] Workflow name matches schema
- [ ] No special characters in workflow name
- [ ] URL structure correct (check documentation)

**Solution:**

1. Run badge health check manually: `gh workflow run badges-health-check.yml`
2. Review issue created with broken links
3. Update schema with correct names/paths
4. Re-run documentation update workflow

### 10.3 Schema Validation Errors

**Error:** "Schema is invalid"

**Checklist:**

- [ ] YAML syntax is correct (no tabs, proper indentation)
- [ ] All required sections present (badges, mapping, config)
- [ ] No duplicate keys
- [ ] Workflow names match actual files

**Solution:**

```bash
# Validate schema
npm run validate:badges-schema

# Fix YAML syntax
# Use YAML linter: https://www.yamllint.com/
```

---

### 10.4 Performance Issues

**Problem:** Badge generation takes >30 seconds

**Causes:**

- Too many workflows in schema
- Network timeout on badge validation
- Large number of documents to update

**Solutions:**

- Reduce number of auto-included badges (via mapping rules)
- Increase timeout threshold in config
- Run on smaller batch of files
- Check GitHub API rate limits

## 11. Best Practices

### 11.1 Do's

✅ **Do:**

- Add markers to important documentation files
- Keep badges minimal (3-5 per document)
- Group related badges together
- Update schema when workflows change
- Review badge changes in PR
- Monitor broken badge issues

---

### 11.2 Don'ts

❌ **Don't:**

- Manually edit content between badge markers
- Remove markers from important documents
- Add custom badges without approval
- Modify schema without code review
- Ignore broken badge issues
- Add badges to auto-generated files
