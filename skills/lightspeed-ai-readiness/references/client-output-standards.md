## Required output qualities

Every client-ready output should be:

- written in UK English
- practical and non-alarmist
- easy to paste into a Google Doc
- clear about assumptions and missing evidence
- separated into client-facing and internal sections where needed
- specific enough to support a proposal, workshop or implementation plan

## Standard sections

Use this structure unless the user asks for another format:

```markdown
# [Client / Project] - [Output Name]

- Value: ...
- Risk: ...
- Next step: ...

## Executive summary

## Current context

## Key findings

## Red flags

## Recommendations

## Prioritised action plan

## Open questions

## Internal LightSpeed notes
```

## Recommendation categories

Classify recommendations as:

1. Quick wins
2. Foundation work
3. Governance work
4. Implementation work
5. Retainer / ongoing improvement

## Readiness language

Use careful phrasing:

- "The current evidence suggests..."
- "This should be confirmed before implementation..."
- "This is a good candidate for a controlled pilot..."
- "This should not be automated without stronger governance..."

Avoid:

- "Fully compliant"
- "Guaranteed safe"
- "AI-ready" without qualification
- "No legal risk"
