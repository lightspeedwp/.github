# Draft Response Output Templates

Use these templates when the user asks for a specific sales response type or when a consistent format would improve review quality.

## Proposal follow-up

```markdown
## Draft

**Subject:** Following up on [proposal/project]

Hi [Name],

Thanks again for taking the time to review [proposal/project]. I wanted to check whether you had any questions or if there is anything you would like us to clarify before you decide on the next step.

Based on our last discussion, the main focus is [confirmed goal or scope]. If helpful, we can walk through the proposal together and identify any areas that need adjusting before approval.

Would you like to book a short call, or would you prefer to send through your comments by email?

Best,
[Sender]

## Internal notes

**Readiness:** safe with edits

**Evidence used**
- [confirmed goal/scope] — [source label]

**Assumptions**
- The customer is still considering the proposal.

**Do not claim yet**
- Final pricing, start date, discount, or delivery timeline unless confirmed.

**Missing details**
- Decision owner and preferred next step.

**Suggested next step**
- Confirm whether they want a call or written revisions.
```

## Discovery recap

```markdown
## Draft

**Subject:** Recap and next steps from our call

Hi [Name],

Thanks for the conversation today. My understanding is that the main priorities are:

- [confirmed priority 1]
- [confirmed priority 2]
- [confirmed priority 3]

The key constraints we noted are [confirmed constraints]. The next sensible step is for us to [safe next step, such as review the current setup / prepare a scoped estimate / confirm technical requirements].

To keep this moving, could you please confirm [smallest missing detail]?

Best,
[Sender]

## Internal notes

**Readiness:** safe with edits

**Evidence used**
- [meeting/call notes] — [source label]

**Assumptions**
- The listed priorities are accepted unless corrected.

**Do not claim yet**
- Technical feasibility, fixed estimate, or timeline until reviewed.

**Missing details**
- [specific missing item]

**Suggested next step**
- Request confirmation of the missing item before proposal work.
```

## Objection-handling reply

```markdown
## Draft

**Subject:** Re: [thread subject]

Hi [Name],

Thanks for raising that. It is a fair point.

Based on what we have reviewed so far, [confirmed answer]. The part I would not want to assume yet is [uncertain point], because we would need to check [source/system/detail] before confirming it.

The safest next step would be to [review / test / scope / schedule a short call] so we can give you a clear answer without overcommitting.

Best,
[Sender]

## Internal notes

**Readiness:** safe with edits / not ready

**Evidence used**
- [confirmed objection/context] — [source label]

**Assumptions**
- [assumption, or “none”]

**Do not claim yet**
- [unsupported promise]

**Missing details**
- [specific evidence needed]

**Suggested next step**
- [recommended action]
```
