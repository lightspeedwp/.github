## Default output style

Use UK English. Keep tone practical, professional and non-alarmist.

Start with:

- Value
- Risks
- Next step

Then provide numbered actions and brief notes.

## Default Markdown document structure

```markdown
# [Client Name] - [Document Title]

## 3-point summary
- Value: ...
- Risks: ...
- Next step: ...

## Project context

## Key findings

## Recommendations

## Quick wins

## Foundation work

## Governance work

## Implementation work

## Open questions

## Internal LightSpeed notes
```

## Client-facing output rules

- Use polished, plain-English language.
- Avoid internal shorthand.
- Avoid implementation details unless needed.
- Explain why each recommendation matters.
- Do not include pricing unless requested.
- Include legal/privacy disclaimer where governance, chatbot, privacy or regulated topics are discussed.

## Internal output rules

Include:

- sales positioning
- delivery risk
- likely service fit
- next meeting agenda
- handover notes for design/development where useful
- unknowns and assumptions

## File naming convention

Use lowercase slugs:

- `[client-slug]-00-readme.md`
- `[client-slug]-01-intake-summary.md`
- `[client-slug]-02-ai-readiness-report.md`
- `[client-slug]-03-governance-discovery-summary.md`
- `[client-slug]-04-ai-governance-guide.md`
- `[client-slug]-05-content-collection-checklist.md`
- `[client-slug]-06-content-gap-report.md`
- `[client-slug]-07-chatbot-planning-brief.md`
- `[client-slug]-08-project-roadmap.md`
- `[client-slug]-09-proposal-line-items.md`
- `[client-slug]-10-next-meeting-agenda.md`

Use this in relevant client-facing outputs:

This document supports operational planning and governance. It is not legal, regulatory or privacy advice. Any legal, regulatory, data-protection or sector-specific obligations should be confirmed with a qualified legal or privacy adviser.
