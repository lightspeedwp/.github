# Launch QA Planning Workflow

## 1. Confirm launch context

Collect:

- current live URL
- staging/dev URL
- Figma design system URL
- Figma prototype URL
- WordPress theme name or repo
- block plugin name or repo, if relevant
- page inventory
- template inventory
- block and pattern inventory
- launch date or target window
- known risks
- available audits or exports

## 2. Classify build type

Classify as:

- block theme only
- block theme plus custom block plugin
- block plugin only
- hybrid theme
- WooCommerce build
- publishing/content-heavy build
- lead-generation build
- AI/chatbot-enabled build

## 3. Define QA workstreams

Create workstreams for:

1. Figma to WordPress parity
2. Block theme QA
3. Block plugin QA
4. Templates and template parts
5. Patterns and reusable sections
6. Content, claims and policies
7. Accessibility and responsive QA
8. Forms, CTAs and conversion paths
9. Analytics and tagging
10. Redirects and SEO migration
11. Schema and AI discoverability
12. Performance and Core Web Vitals
13. Launch operations and rollback

## 4. Build QA matrices

Each matrix should include:

- item/page/template/block
- expected behaviour
- evidence source
- status
- severity
- owner
- notes
- retest status

## 5. Define launch gates

Use the launch gate model to classify findings.

## 6. Route specialist work

Route detailed audits to the relevant specialist skills where needed.

## 7. Produce planning summary

Summarise:

- what is ready
- what is pending
- launch blockers
- must-fix items
- accepted risks
- post-launch backlog
- next specialist audit
