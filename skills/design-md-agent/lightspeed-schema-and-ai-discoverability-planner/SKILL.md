# LightSpeed Schema and AI Discoverability Planner

## Purpose

Turn approved or near-final website content into practical schema, internal-linking and AI-search discoverability guidance for WordPress website launches.

Use this skill after content collection, content generation or readiness assessment has produced page drafts, page briefs, FAQs, claim registers, source-of-truth notes or launch plans.

## Core rules

- Do not guarantee rankings, rich results, featured snippets, AI citations, voice-search visibility, traffic or ROI.
- Treat schema as eligibility and clarity support, not a guarantee.
- Use only approved or review-ready content for schema recommendations.
- Do not add FAQ schema for hidden, collapsed-only-without-visible-content, unpublished or unapproved FAQ answers.
- Flag unsupported claims as `Evidence Required`.
- Separate public-facing wording from internal implementation notes.
- Use UK English and a practical, non-hype tone.

## Inputs to accept

Accept any combination of:

- website page list or sitemap
- approved website copy
- page briefs
- service and solution page drafts
- FAQ source libraries
- company FAQ page drafts
- claim registers
- source-of-truth registers
- AI readiness assessment outputs
- content collection outputs
- Search Console notes
- GA4 notes

- schema validation results
- internal linking plans

If input evidence is missing, create a safe schema/discoverability plan and list the missing evidence rather than pretending validation has been completed.

## Workflow

1. Confirm the website/project context and page set.
2. Identify source status: Approved, Needs Review, Evidence Required, Legal Review or Not for Chatbot.
3. Classify each page by page type: homepage, service, solution, article, case study, FAQ, policy, contact or landing page.
4. Recommend schema types per page.
5. Map FAQs to visible pages and mark which are eligible for FAQPage schema.
6. Recommend internal links based on user intent, service hierarchy and entity clarity.
7. Rewrite AI/search claims safely where needed.
8. Create an AI visibility baseline checklist.
9. Create validation and post-launch monitoring tasks.
10. End with internal notes, missing evidence and next actions.
