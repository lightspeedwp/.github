# Accessibility Statement Guidance

Accessibility statements should be honest, specific and actionable.

## Cover

- commitment to accessible, inclusive WordPress experiences
- target standard, if known
- known limitations
- feedback/contact route
- review date
- testing methods used
- planned improvements

## Do not claim

- full WCAG compliance unless verified
- no accessibility issues
- guaranteed compatibility with all assistive technology

## Recommended language

Use:

- "we aim to"
- "we are working towards"
- "tested using"
- "known issues"
- "please contact us if you experience a barrier"

## Testing references

Mention testing only if performed:

- keyboard navigation
- visible focus states
- colour contrast
- screen-reader spot checks
- form labels and errors
- mobile/responsive checks
- light/dark mode contrast
